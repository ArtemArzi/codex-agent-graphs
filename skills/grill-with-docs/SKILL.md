# Grill with Docs

Combine the available `grilling` and `domain-modeling` skills inside the same
task. Grilling owns the interview and follow-up questions; domain-modeling owns
agreed terms and qualifying durable decisions. Do not start a second interview
or replace Project Start, the project specification or its implementation owner.

Resolve document owners through the project map before writing. Save decisions
as they are settled, distinguishing accepted rules, proposals and unknowns.
Reuse existing glossary/domain/decision sections; create a document only when
there is resolved content and no owner. A pending question is not a decision.

If either companion is unavailable, perform that bounded discipline directly:
ask consequential ready questions, follow the answers, and record agreed
definitions/reasons with the existing owner. Do not install dependencies or
run setup just to continue the interview. Return the understanding, document
paths and consequential open questions. Continue already-authorized work once
its prerequisites are settled; an interview alone does not authorize code or
external publication.
