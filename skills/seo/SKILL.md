# SEO

Use the actual site, market and selected search engines. Technical correctness
supports eligibility; it cannot promise indexing, positions or traffic. This
skill supports technical, editorial and link/local work independently. Select
only the branches the request needs; an audit does not imply redesign or rollout.

Read nearest instructions, docs map, current quality/URL/content owners and
known decisions. Recover existing routes, languages, canonical origin and
migration policy. Never invent business facts, domains, regional variants or
search-console IDs. Keep requested scope; a technical audit is not a content
plan or redesign. Continue authorised fixes through the existing task owner;
audit alone does not grant release/account/index submission actions.

## Technical work

Read [technical-profiles.md](references/technical-profiles.md) for common URL
checks and Google/Yandex/both differences. Observe each applicable route's HTTP,
body/format, source/rendered content and indexing directives. A robots/sitemap
200, one canonical found in a repository or a single Lighthouse score cannot
establish per-URL correctness. Preserve existing URLs by default; a necessary
change needs reviewed old→new mapping and compatibility checks.

Include a useful error page and the actual HTTP response for an unknown URL,
not just a standalone `/404` design. Inspect a narrow mobile viewport and desktop
when changing that template. Verify CMS publication and updates against the
resulting HTML and cache when freshness is part of the task.

Use available web-measurement for GSC/Webmaster identity, roles and account
evidence; do not duplicate its measurement protocol. Search-engine choice does
not automatically select GA4/Metrika. Use project-native browser/check commands
and optional compatible tools; do not automatically install scanners or upload
repository data.

## Editorial work when requested

Read [editorial.md](references/editorial.md) for intent/keyword mapping,
titles/descriptions, headings, linking and content-grounded schema. Existing
editorial workflows remain available; they are not mandatory during a technical
site check. Length/H1/FAQ advice is contextual guidance, not an indexing rule.

## Links and local presence when relevant

Read [links-and-local.md](references/links-and-local.md) for internal link paths,
orphan pages, backlink evidence, local business profiles and paid placements.
Internal links, outgoing references, incoming links and brand mentions are
different observations. A missing backlink-data tool leaves counts unknown.
Evaluate paid placements against their audience and actual terms; an SEO request
does not authorise purchases, outreach or profile changes.

For questions about being found or cited by AI search products, use the available
[AI Search Visibility](../ai-search-visibility/SKILL.md) skill. Reuse applicable
SEO evidence instead of repeating a full audit. SEO remains usable alone; an
unavailable companion does not block the requested SEO work.

Report exact pages, observed problem, proposed/applied change and actual checks
in the user's language. Use the shared
[evidence contract](../website-standards/references/evidence.md) and existing
project quality format; absent companion is disclosed, not installed silently.
Distinguish source hints, published artifact, crawlability, actual index state,
impressions, clicks and business outcome. Required missing evidence stays unknown.
For each material finding give the affected URL/template, observation and source,
practical consequence, proposed/applied fix, priority with a reason, and its
verification. State route coverage and exclusions; do not manufacture a /100
health score or numeric impact from incomplete observations. Preserve the
existing task/report owner and its next step rather than creating another backlog.
Read [sources.md](references/sources.md) when provider guidance needs refreshing.
