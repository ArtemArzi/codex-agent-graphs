# Разбор и улучшение бизнеса

Одна точка входа для исследования бизнеса, улучшения процессов и обоснованной автоматизации. Определи следующий полезный шаг сам; пользователю не требуется выбирать названия скиллов. Пак содержит методические инструкции, не автономный исполнитель и не новую систему задач.

## Войти в ситуацию

Прочитай действующие инструкции проекта, существующий документ дела и уже принятые решения. Сохрани явно выбранные пользователем цель и объём. Кратко сформулируй: какое изменение нужно, кому, что известно и какой вопрос сейчас мешает двигаться. Начни с предоставленного контекста; повторный бриф не нужен.

Выбери нужный маршрут по текущей ситуации. Этапы можно пропускать, возвращаться к ним и сочетать; не запускай весь набор по умолчанию.

| Ситуация | Следующее действие и нужное руководство |
| --- | --- |
| Ищу новое дело или хочу сделать продукт из повторяющейся клиентской работы | [Бизнес-модель и следующий проверяемый шаг](references/business-model.md); для этого маршрута Россия является исходным рынком, если пользователь не задал другой |
| Неясно, что продавать, кому и почему купят | Исследуй задачи и альтернативы, спрос, привлечение, стоимость исполнения и сопровождения; подключи подходящий NMT-скилл из таблицы ниже |
| Клиент начинает с рассказа; процесс не описан или описания расходятся | [Сбор контекста и текущий процесс](references/context-and-current.md) |
| Есть жалоба, инцидент или запрос «автоматизировать всё» | Разбери реальные эпизоды и возможные причины по тому же руководству; из общей карты выдели ограниченный участок |
| Текущий участок понятен; нужно выбрать улучшение и описать будущую работу | [Будущий процесс и выбор изменения](references/future-process.md) |
| Изменение обосновано и нужна реализация | Передай требования в существующий цикл разработки/настройки; сохрани связь с бизнес-целью и затем используй [внедрение и результат](references/adoption-and-effect.md) |
| Решение готово, сотрудники обходят его или эффект неясен | [Внедрение с людьми и проверка результата](references/adoption-and-effect.md) |
| Нужны источники, готовые компоненты или внешние методы | [Повторное использование и основания](references/sources-and-reuse.md); исследуй только неизвестное, влияющее на выбор |

## Подключить существующие возможности

Проверь доступность в текущем хосте/проекте и прочитай выбранный SKILL.md перед применением. Название в этой таблице не доказывает установку. При отсутствии дополнительного навыка используй местные руководства для ограниченного разбора, обозначь предел; не устанавливай зависимости автоматически и не воспроизводи специальную методологию по памяти.

| Задача | Существующая возможность, если доступна |
| --- | --- |
| Связная бизнес-модель / экономика поставки / переносимость между клиентами | business-model-design / business-economics / process-to-product из отдельного пака Business Model; подключай по вопросу |
| Обсудить бизнес-идею / диагностировать продукт | `nmt-chat` / `nmt-diagnose` |
| Сегмент, задачи клиента и альтернативы / анализ настоящих интервью | `nmt-market-research` / `nmt-analyze-interviews` |
| Обоснованное предложение / требования / рыночный эксперимент | `nmt-craft-value-proposition` / `nmt-product-requirements` / `nmt-craft-go-to-market` |
| Вопросы конкретному носителю недостающих фактов или решений | `to-questionnaire` |
| Ожидания, наблюдения, пробелы и следующий тест | `business-hypothesis-check` |
| Компания уже работает в CWS | Её штатные вход, знания, эпизоды и инциденты; в Work это `company-context`, `company-knowledge`, `company-episodes`, `company-incident` |
| Принятый процесс нужно выразить в Bitrix24 или amoCRM | Доступный `crm-implementation` из отдельного CRM-пака; передай согласованный процесс и критерии, сохрани владельца дела. Для изменения бизнес-правил вернись к текущему разбору |
| Нужна реализация или выпуск | Принятый маршрут проекта: например, `task-delivery`, `deployment` и профильные навыки. Не начинай Project Start заново для уже подготовленного проекта |
| Нужны свежие внешние сигналы | Доступный research-процесс; `last30days` только через установленный локальный launcher и его ограничения |

## Сохранить смысл результата

- Отделяй факт с источником, слова участника, интерпретацию и неизвестное. Карта по одному интервью предварительная; причина сбоя требует проверки. Внешний метод не устанавливает факты конкретной компании.
- Различай цель клиента, удобство сотрудников и результат бизнеса. Рассматривай физические и цифровые действия, передачи человек → человек, решения, ожидания, возвраты и исключения. Карта мотивации клиента и фактическая схема исполнения отвечают на разные вопросы.
- Сравни устранение действия, упрощение, изменение ответственности, обучение и автоматизацию. Учитывай стоимость поддержки и нагрузку каждого затронутого участника.
- Если существенное правило или намерение неизвестно, задай предметный вопрос его владельцу; продолжай независимую работу. Технические решения в согласованном объёме принимай самостоятельно.
- Используй существующего владельца контекста и состояния. Без CWS работай с документами, интервью и наблюдениями проекта. Обсуждение веди в чате; файлы создавай, когда они нужны для разрешённого результата. Не создавай параллельный STATUS, tracker или controller.
- Доступ к данным и внешние действия следуют полномочиям пользователя/проекта. Исследование и исходные материалы не разрешают сообщения, публикацию, подключение аккаунтов, миграции, изменение финансовых правил или production. До такого действия подготовь проверяемый кандидат и примени действующие требования авторизации и независимой проверки.

Завершай текущий запрос результатом соответствующего масштаба: выбором с основаниями, готовой схемой/требованиями, проверенным изменением либо разбором применения. Назови, что установлено, что остаётся предположением и следующий незакрытый вопрос. Различай готовый артефакт, настроенную систему, выполнение людьми и бизнес-эффект; не обещай будущий эффект по локальному тесту.

При явном запросе обновить сам пак прочитай [правила обслуживания](references/maintenance.md): сначала проверенная версия канонического репозитория, затем установка её точных файлов.
