# Interface Clarity

Make the selected screen answer the visitor's actual questions and support their
next decision. Treat text, grouping, prominence and action consequences together.
This skill owns content clarity and its evidence, not a full design system,
SEO audit, campaign controller or promise of conversion growth.

## Ground the task

Read the project's instructions, audience/task evidence, factual content owner,
existing design/voice decisions and current surface. Recover known facts before
asking questions. Identify what the person needs to understand and do in this
state; label assumed needs as hypotheses. An interview, support question or
observed error is stronger grounding than an invented persona.

Choose what the request needs: plan the content, review an existing surface,
rewrite specific messages, or evaluate a change. Use
[content-and-layout.md](references/content-and-layout.md) for message function,
placement and hierarchy. Keep accepted scope, terminology and brand character.
Preserve factual, commercial, privacy and legal meaning; unsupported facts stay
unknown. A vague claim can be removed or queried, not replaced with an invented
price, guarantee, author credential or timing promise.

## Work from the available evidence

Inspect the real screen/flow when assessing layout. Reuse relevant current
screenshots and browser observations; capture only missing states. Tie findings
to the actual version, viewport and state. For a text-only request, review the
words and propose placement, explicitly leaving visual execution unverified.
Source code can support a proposed diagnosis; it is not a viewed screen.

For each material issue, connect the visitor's question → current text/placement
→ likely or observed misunderstanding → concrete change → verification.
Separate observed layout defects, expert hypotheses and real participant results.
A screenshot does not establish where people looked or what they understood.
Do not simulate human comprehension statistics with an LLM or invented testers.

Use [measurement.md](references/measurement.md) when choosing metrics or testing
understanding. It distinguishes criteria coverage, human paraphrase, first action,
task completion and production behaviour. Use counts and defined denominators
where measured. An editorial score or word count is not a comprehension result;
no universal /100 clarity score or five-second pass gate is required.

## Deliver and verify

Return a small set of prioritised changes with exact screen/element, evidence,
proposed wording and placement, reason and check. When content structure is the
task, a compact question/answer/placement/action map can be useful. Do not force a
full-page template onto a label edit. State readiness per affected criterion as
observed, concern, not checked or not applicable; do not average away a serious
misunderstanding of payment, booking, deletion or data submission.

Continue authorised implementation through the existing project owner. A review
alone does not authorise a redesign, publication, analytics installation or real
submission. For changed UI, inspect its affected desktop and narrow mobile states
and consequences with project-native checks. Report local, preview and public
evidence separately. Save findings/decisions in the existing project task or
quality document, not a new global registry. Communicate in the user's language.

For combined text/design work, read
[design-collaboration.md](references/design-collaboration.md). Reuse its shared
brief and findings with available `impeccable:impeccable` and the relevant
`product-design` skill. Start with the capability matching the request and bring
in the other only for a concrete gap; there is no fixed three-skill sequence.
After visual changes, check that the accepted wording, conditions and next-action
meaning survived in the rendered screen. Do not repeat a completed equivalent
audit or claim a plugin ran when only this collaboration guidance was used.

Brand Voice owns a requested voice profile, SEO owns search intent/metadata, and
Web Measurement owns existing account/event evidence. Missing tools leave the
affected check unverified; continue supported work without automatic installation.

Read [sources.md](references/sources.md) for researched methods, provenance and
which recommendations are contextual rather than universal standards.
