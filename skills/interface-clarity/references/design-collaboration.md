# Work with Impeccable and Product Design

Use this reference when a task combines content clarity with visual execution,
design exploration or an existing-flow audit. It is a handoff agreement, not a
new workflow runner. Resolve the actual available skill names through the host
catalog; do not pin plugin cache paths or load every plugin reference.

| Need | Capability and handoff |
| --- | --- |
| What the visitor must understand; truthful wording, answer order, action consequence | Interface Clarity prepares or checks the content decisions |
| Visual implementation or refinement: typography, emphasis, grouping, spacing, responsive layout | Available `impeccable:impeccable`, selecting the relevant operation such as clarify, typeset or layout from the actual request |
| Research/exploration, selected visual source or a broader existing-flow audit | Available Product Design; use its router for the requested workflow, and `product-design:audit` for an actual flow audit |
| Confirm that design changes preserved the content decision | Interface Clarity reads the resulting affected screen/state and rechecks the specific acceptance criteria |

An ordinary implementation is not automatically a Product Design workflow.
Direct Product Design requests retain that plugin's own routing, source capture,
context, visual-choice and verification contracts. Direct Impeccable requests
retain its own context and operation rules. This companion does not bypass
required source selection, approvals or the host's scope/review policies.

## Enter from the requested capability

- A clarity/text request starts with the selected words and visitor task. Pull
  in visual help only if placement or execution needs work; a single label edit
  does not need both design plugins.
- An Impeccable-led screen change can reuse Interface Clarity when unclear offer,
  message order, conditions or action consequences are material. Supply the
  current screen and facts; return concrete content decisions to the visual owner.
- A Product Design-led audit/exploration can reuse Interface Clarity for the same
  content questions. Retain its current capture/brief and source fidelity; add
  findings to the existing report rather than launching an unrelated second audit.

These are collaboration routes to apply when the companion is loaded; they do
not prove that an independently invoked plugin automatically called this skill.
Product Design may read the user's saved team-convention pointer through its
native context preflight. Installed instructions are not runtime invocation proof.

## Pass the smallest useful shared context

Reuse the owning project brief/task. Carry the target URL/file and version,
current viewport/state or capture, actual audience/task, confirmed facts and
constraints, accepted copy/terms, proposed placement and unresolved questions.
For a narrow change this can be a few lines, not another required artifact.

Keep which facts are confirmed, which copy is approved, which design choices
are proposed and which checks are missing. Do not re-interview settled decisions,
recreate customer research or rewrite promises for visual convenience. Source
captures from the design workflow remain the reference for fidelity; a content
proposal is not permission to change a pinned design or commercial condition.

## Reconcile the result

The visual owner returns the actual rendered target and affected state evidence.
Check the accepted answer, meaningful labels, important conditions and supported
next action on desktop/narrow mobile when affected. Use human observations for
human understanding; an attractive screen or model critique is not that evidence.
Fix specific mismatches through the current owner and retain the valid earlier
checks. State any unavailable capture/tool and resulting limit.

One report/task owns the outcome and next step. Do not require Impeccable polish
plus Product Design audit plus another global review by default. Use a broader
audit when it answers a distinct requested question; finish a scoped correction
once its affected criteria have adequate evidence.
