# Поддержка документации

Maintenance отвечает на один вопрос: расходятся ли канонические документы с проверенным состоянием проекта?

## Классы результата

- `no-change` — документы уже точны; файловая дельта пуста.
- `factual` — отражены проверяемые факты: пути, команды, версии, завершённая реализация, тесты, владельцы или карта модулей. Согласование не требуется.
- `semantic` — меняются продуктовая семантика, публичный договор, архитектурная власть, риск или полномочия. Сначала `decision-required`, затем правка со ссылкой на решённый `decision.id`.

## Быстрый порядок

1. Проверь change receipt, если он есть, и затронутый путь выполнения.
2. Прочитай только канонические документы и ближайшие `AGENTS.md`, связанные с изменением.
3. Сравни утверждения с репозиторием. Не проводи внешний research, если факты полностью внутренние.
4. Исправь минимальный связный набор. Если дельты нет, не «улучшай стиль» ради активности.
5. Выбери self-проверку по умолчанию. Независимая проверка нужна при широкой дельте, security/compliance, изменении публичного договора, низкой уверенности или конфликтующих доказательствах.

Runner отдельно сравнивает канонические документы и все `AGENTS.md` с последним operational snapshot. Поэтому внешний дрейф нельзя выдать за `no-change`, а новый вложенный `AGENTS.md` проходит те же содержательные проверки, даже если появился до `init`. Изменения неканонических заметок между runs сами по себе не расширяют authority set.

## Вложенные AGENTS.md

Создай новый файл только если каталог является стабильной границей владения и корневого файла уже недостаточно. Он должен быть обычным файлом внутри репозитория и содержать заполненные разделы:

- `Scope` / `Область`;
- `Map` / `Карта`;
- `Commands` / `Команды`;
- `Boundaries` / `Границы`.

Не создавай такие файлы автоматически по каждой папке, числу файлов или глубине дерева. Hooks только обнаруживают вероятный дрейф и запускают аудит; смысл пишет модель.

## Наследование старых проектов

Первый v3 maintenance run может взять канонический набор из старого `artifacts` state. После успешного завершения владелец набора — `graph_v3.canonical_docs`; старые поля остаются для совместимости Task Delivery.
