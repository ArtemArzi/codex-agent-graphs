# Основания устройства навыка

Это снимок исследований на 2026-07-19, а не замена текущей документации конкретной технологии.

## Первичные источники

- [OpenAI: Harness engineering](https://openai.com/index/harness-engineering/) — качество длинной работы зависит от наблюдаемой среды, исполняемых ограничений, коротких циклов обратной связи и читаемости репозитория для агента.
- [OpenAI Codex: Subagents](https://developers.openai.com/codex/subagents) и [AGENTS.md](https://developers.openai.com/codex/guides/agents-md) — специализированные роли, ограниченный контекст, явные инструкции и осторожная делегация; сабагенты увеличивают расход токенов.
- [OpenAI Cookbook: Codex execution plans](https://developers.openai.com/cookbook/articles/codex_exec_plans) — план для длинной задачи должен быть живым, самодостаточным и регулярно перечитываться.
- [OpenAI: Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/) — задачи полезно вести как явный автомат с зависимостями, блокерами и ограничениями времени/токенов.
- [Google Research: scaling agent systems](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) — параллельные агенты помогают на распараллеливаемых задачах, но вредят последовательному планированию и усиливают независимые ошибки без центральной проверки.
- [SWE-Replay](https://arxiv.org/abs/2601.22129) — повторное использование полезного промежуточного состояния способно снижать стоимость; важен сохранённый лучший известный рубеж, а не полный перезапуск.
- [Scaling Test-Time Compute for Agentic Coding](https://arxiv.org/abs/2604.16529) — компактные структурированные сводки гипотез, прогресса и неудач помогают выбору и последовательному уточнению.
- [Agentic Verifier](https://arxiv.org/abs/2602.04254) — активный поиск различающих контрпримеров сильнее случайного набора тестов; результат статьи получен в задачах программирования и переносится как принцип, не как универсальная цифра.
- [Auditing Reward Hackability in Code RL Training Environments](https://arxiv.org/abs/2606.16062) — тестовые оракулы и сгенерированные проверки могут быть обходимыми, поэтому новый тест надо отдельно проверять на эталонном и неверном поведении.
- [Evaluating Plan Compliance in Autonomous Programming Agents](https://arxiv.org/abs/2604.12147) — хороший явный план помогает, плохой может быть хуже отсутствия; периодическое напоминание плана полезно, а лишние стадии способны мешать.
- [SWE-Review](https://arxiv.org/abs/2607.06065) — цикл «создание — обзор по репозиторию — исправление» улучшает решение по сравнению с одноразовым обзором в фиксированном контексте.
- [GitHub: better tools made code review worse](https://github.blog/ai-and-ml/github-copilot/better-tools-made-copilot-code-review-worse-heres-how-we-actually-improved-it/) — обзор должен начинаться с изменения и собирать минимальный окружающий контекст; неверно заданный поиск создаёт дорогие циклы.
- [GitHub: reviewing agent pull requests](https://github.blog/ai-and-ml/generative-ai/agent-pull-requests-are-everywhere-heres-how-to-review-them/) — отдельно проверяй ослабление CI, удалённые/пропущенные тесты и дублирование существующих помощников.
- [Anthropic: coding expertise](https://www.anthropic.com/research/claude-code-expertise) — агент часто берёт на себя способ реализации, но знание предметной области человека продолжает заметно влиять на успех.
- [METR: 2026 uplift update](https://metr.org/blog/2026-02-24-uplift-update/) — старые оценки ускорения быстро устаревают и зависят от отбора задач; не обещай фиксированный выигрыш от агента.

## Практический вывод

Навык поэтому:

- хранит точные промежуточные доказательства и их отпечатки;
- проверяет план до реализации и перечитывает его между частями;
- предпочитает один управляемый маршрут рою агентов;
- использует параллельность только для независимых чтений или блоков;
- требует активного проверяющего по риску и всегда проверяет сам тестовый оракул;
- превращает повторяемые замечания в исполняемые ограничения;
- обнаруживает MCP-возможности только для относящегося внешнего/live вопроса,
  применяет релевантный сервер при наличии и не подменяет проверку одним лишь
  именем в конфигурации.
