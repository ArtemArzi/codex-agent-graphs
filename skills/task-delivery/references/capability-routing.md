# Подбор навыков, MCP, инструментов и хуков

## Главный принцип

Всегда начинай с MCP discovery, затем выбирай возможность под конкретный вопрос, а не вопрос под имеющийся инструмент. Релевантный MCP используй обязательно; отсутствие подходящего или успешного сервера фиксируй как явный fallback.

```text
потребность задачи
-> реально доступные возможности
-> минимальный достаточный набор
-> полномочия и внешние последствия
-> запасной путь
```

Файл в каталоге или секция в `config.toml` означает «кандидат». Реальной возможностью считается только то, что присутствует в каталоге навыков или инструментов текущего запуска и может быть вызвано с текущими правами.

## Как провести живой осмотр

1. Выдели 1–3 термина задачи: стек, внешняя система или тип проверки.
2. Прочитай относящиеся совпадения в списке навыков, переданном текущей средой. Файловый осмотр нужен для сверки, но не доказывает, что навык уже подхвачен сеансом.
3. Прочитай текущий каталог инструментов. Если доступен поиск инструментов, ищи по нужной системе и действию, а не загружай весь каталог в контекст.
4. Запусти `inventory --match <термин>`; он выводит только имена совпавших кандидатов и счётчики остального, не значения ключей, токены или команды окружения.
5. Различай три статуса: `configured` — имя найдено в настройке; `advertised` — возможность объявлена текущей средой; `verified-callable` — минимальный безопасный вызов только на чтение реально прошёл. Зависеть от MCP/app/browser можно только в третьем статусе.
6. Сопоставь кандидаты с вызываемыми инструментами и сохрани квитанцию preflight. Запиши несовпадения в `CAPABILITIES.md`.
7. Для хуков отдельно запиши `configured-only`, `observed` или `absent`; наличие манифеста не доказывает срабатывание.
8. Перед внешней записью проверь полномочия и точную область действия. Для `access=read-write` сохрани источник, область и квитанцию разрешения в машинном блоке; чтение не даёт права писать.

Для приложений используй их обычные инструменты и поиск инструментов. Не вызывай `list_mcp_resources` или `list_mcp_resource_templates` ради приложения. Эти команды полезны только для не-приложенческого MCP, который публикует относящийся к задаче ресурс.

## Что выбирать

| Потребность | Предпочтительная возможность | Когда обязательна | Запасной путь |
|---|---|---|---|
| Поиск и трассировка локального кода | `rg`, Git, LSP, тестовый раннер | Почти всегда для внутреннего исследования | Адресное чтение файлов |
| Текущая документация OpenAI | `openaiDeveloperDocs`, навык `openai-docs` | Любая меняющаяся деталь Codex/OpenAI | Официальный сайт OpenAI |
| Документация библиотеки | `context7` или официальный сайт/репозиторий | Когда план зависит от версии или поведения библиотеки | Исходный код установленной версии |
| Внешний поиск | Exa/Tavily/Firecrawl MCP; затем первичный официальный источник | Когда внешняя деталь влияет на решение | Обычный веб-поиск с первичной проверкой |
| Научная статья | arXiv или сайт издателя/авторов | Когда вывод опирается на исследование | Официальная копия статьи |
| GitHub, PR, issue, CI | GitHub MCP или приложение | Когда удалённое состояние является частью задачи | `gh` только при доступной авторизации |
| Linear/Jira/Notion/Drive | соответствующее приложение | Когда там находится канонический контекст | Попросить экспорт или ссылку |
| Реальный интерфейс | Playwright, Browser, Chrome или Computer Use | Когда критерий приёмки наблюдаем в интерфейсе | Локальный e2e/скриншот с оговоркой |
| Доступность интерфейса | `access-lint` плюс ручной путь | Для пользовательского интерфейса с затронутой доступностью | Локальный анализатор |
| Безопасность | Codex Security или проектный сканер | Для отдельного запроса на сканирование или высокого риска | Адресная модель угроз и тесты |
| Проектирование UI | `ui-ux-pro`, Pencil, профильные навыки | Только при реальной задаче дизайна | Существующая дизайн-система |
| Живая аналитика/SEO | Yandex Metrika/Webmaster | Когда решение требует реальных данных сайта | Сохранённая выгрузка с датой |

Не запускай сразу несколько поисковых MCP с одинаковой целью. Начни с одного наиболее прямого MCP и открой найденный первичный источник; второй инструмент нужен для пробела, проверки расхождения или недоступной страницы. Preflight должен быть минимальным: чтение метаданных, одной известной страницы или одного безопасного объекта, без массовой выгрузки.

## Условные навыки

Не образуй постоянную цепочку. Выбирай только применимые навыки:

- `project-start` — проверить, открыт ли этап реализации; не дублировать его бизнес-, стековый и архитектурный цикл;
- `research` — один ограниченный внешний вопрос и отчёт по первичным источникам;
- `prototype` — один спорный вопрос, одноразовый результат, без скрытой ветки или коммита;
- `codebase-design` — изменение шва, интерфейса модуля или направления зависимости;
- `coding-standards` — дополнение к правилам выбранного стека, но не замена проектным соглашениям;
- `eval-harness` — агент, подсказка, модель, инструментальный маршрут или другой вероятностный результат;
- `ai-regression-testing` — поведение API, сервера, изоляции, флага или регрессии, где нужен устойчивый оракул;
- `e2e-testing` — реальный пользовательский путь в интерфейсе;
- профильные навыки безопасности — только по поверхности риска;
- стековые навыки плагинов — когда стек и версия совпадают.

Не вызывай автоматически GSD-планирование, GSD-реализацию, `wayfinder`, `to-spec` или `to-tickets`. Они могут владеть более крупным циклом или писать во внешнюю систему. Используй их лишь по явному запросу либо когда репозиторий уже выбрал их как канонический маршрут.

При implementation delegation root выбирает для packet максимум три применимых skills с причиной и обязательностью. Worker загружает их из каталога своего запуска, а не получает копию всего skill-контекста. Required skill должен появиться как `applied` в `capabilities_used`; если он недоступен, worker возвращает `needs_context`. MCP evidence можно передать как `provided` либо потребовать безопасный `call-required`; имя в конфигурации без реального receipt не считается контекстом.

## Договор с хуками

Живой осмотр на 2026-07-19 показал локальный слой хуков со следующими функциями:

- узкие запреты разрушительных и обходящих защиту команд, предупреждение о секретах;
- фиксация только подтверждённых сбоев инструментов;
- компактный контекст при старте, сжатии, завершении и работе сабагентов.

Это подсказка, а не вечная конфигурация. Каждый запуск должен обнаружить фактические события. При наличии такого слоя:

- не включай обходные переменные и не правь конфигурацию хука;
- не копируй сырые команды и весь вывод в новый журнал;
- используй предупреждение хука как сигнал пересмотреть действие;
- при диагностике читай журнал только адресно и учитывай, что он может быть неполным;
- явный пакет сабагенту всё равно обязателен: сохранённый дайджест не заменяет цель, область, пути и критерии;
- после сжатия перечитай состояние задачи, даже если хук вернул хороший пересказ.

## Текущий профиль пользователя как подсказка

На 2026-07-19 в двух установках были замечены:

- рабочие навыки `project-start`, `research`, `prototype`, `codebase-design`, `grilling`, `domain-modeling`, `grill-with-docs`, `setup-matt-pocock-skills`, `to-spec`, `to-tickets`, `wayfinder`;
- качественные навыки `eval-harness`, `ai-regression-testing`, `e2e-testing`, `coding-standards`, многочисленные навыки безопасности и стековые практики;
- кандидаты MCP для официальной документации, поиска, GitHub, браузера, доступности, дизайна, аналитики и научных публикаций;
- приложения GitHub, Linear, Notion, Google Drive, Canva и другие.

Не считай этот список доказательством доступности. Он нужен только для разумных поисковых подсказок. Не устанавливай отсутствующий компонент автоматически.

## Минимальное содержание `CAPABILITIES.md`

- дата и среда;
- применимые инструкции и источник задачи;
- хуки и их события;
- выбранные навыки: цель, причина, запись/побочный эффект, запасной путь;
- выбранные MCP/инструменты: цель, режим доступа, требуемое разрешение, запасной путь;
- относящиеся, но не выбранные возможности и причина;
- расхождения «настроено, но не вызывается»;
- итог: набор достаточен / есть блокер.
