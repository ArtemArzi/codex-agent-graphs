# Определения метрик и денег

Перед расчётом запиши сущность/идентификатор, владельца, источник, числитель/знаменатель, период/часовой пояс, окно дозревания, исключения, единицы, состав затрат и свежесть. Уважай принятую учётную основу компании: поступления денег, признанная выручка и выполненный заказ могут относиться к разным периодам.

| Величина | Проверяемое определение | Что не смешивать |
| --- | --- | --- |
| Принятое обращение | Уникальные lead_id по принятым правилам, без тестов/спама/дублей | Submit формы и клик по телефону ещё не доказывают принятие |
| Подходящее обращение | Соответствует явным условиям услуги, территории и возможности исполнения | Отказ компании из-за отсутствия слотов не обязательно плохой лид |
| Контакт | Есть двусторонний разговор/ответ | Попытка звонка не равна контакту |
| Запись/заказ | Принятые компанией условия следующего исполнения | Оплата, бронь, выполнение, перенос и возврат - отдельные события |
| Конверсия | Результаты из дозревшей когорты / исходные единицы той же когорты | Оплаты старых обращений нельзя делить на все обращения новой недели |
| CPL | Определённые затраты / согласованные обращения | Назови состав затрат и вид обращения; unknown затраты не ноль |
| Стоимость новых покупателей | Определённые затраты привлечения / новые платящие клиенты той же области | Media CAC, blended CAC и spend per all new payers имеют разную область; атрибуция/полнота источника существенны |
| ROAS | Атрибутированная ценность/выручка / рекламные затраты | Не прибыль и не дополнительный эффект; уточни возвраты и модель |
| Вклад до маркетинга | Сопоставимый доход/чистые поступления по выбранной основе минус согласованные переменные затраты исполнения | Нельзя назвать это чистой прибылью без остальных затрат |
| Вклад после маркетинга | Предыдущая величина минус согласованные маркетинговые затраты | Не вычитай один расход дважды и не придумывай распределение каналам |
| Повтор | Клиенты с последующей покупкой в окне / клиенты, полностью прожившие окно | Последняя неделя ещё не прожила год; прогноз LTV не заработанные деньги |
| Покрытие источника/связи | Записи с известным источником/сопоставленным заказом / все ожидаемые записи | Unknown показывается отдельно; self-report не затирает UTM |
| Мощность и качество | Продаваемые свободные слоты/часы; отмены, неявки, жалобы и время ответа | Дополнительный спрос может быть непосильным и вредным |

Если знаменатель равен нулю, отношение не определено; если данных нет, оно unknown. При неполных источниках рассчитай только известную часть и покажи, при каком неизвестном решение меняется. Для бизнес-модели/денежных сроков используй доступный business-economics.

## Синтетический пример

За период 50 выполненных услуг по 5 000 ₽ дали 250 000 ₽ поступлений; возвраты 25 000 ₽; переменные затраты по всем выполненным услугам 125 000 ₽; реклама 100 000 ₽. На этой упрощённой денежной основе: после возвратов 225 000 ₽; вклад до маркетинга 100 000 ₽; после рекламы 0 ₽. Постоянные расходы и труд неизвестны, поэтому утверждать прибыль нельзя. Возвращённая оплата не отменяет уже понесённую себестоимость автоматически.

Кабинетный ROAS 2,5 может использовать поступления до возвратов и свои правила присвоения источника. Он не меняет этот ограниченный расчёт в доказанную дополнительную прибыль. Если источник известен лишь у половины покупателей, нельзя распределить весь доход каналам; если свободных слотов нет, удвоение бюджета требует отдельного обоснования, даже при положительном наблюдаемом вкладе.

50 исполнений / 200 обращений = 25% как отношение потоков. Только при связи одних и тех же дозревших обращений и исполнений это конверсия когорты. Не предполагай эту связь из одинакового календарного месяца.

## Связь платформы с учётом

Источником согласованных статусов служит принятый учёт компании. Аналитика содержит их проекции и правила связи с источниками. Проверяй order/customer/lead IDs, время переходов, новые/повторные, отмены/возвраты, назначение эксперименту и причину потери. HTTP-успех импорта не доказывает привязку, полноту или доставку сигнала в рекламный продукт.

Для Яндекса проверяй актуальные модели/окна/место проверки в текущей справке: они меняются и могут содержать предупреждения о качестве отчётных статусов. Не замораживай эти технические значения в универсальном навыке. [Официальные источники](../../marketing-work/references/method-sources.md).
