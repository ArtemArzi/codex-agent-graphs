# Что переносится между клиентами

Используй при сравнении нескольких поставок или проектировании следующего
различающего теста. При недостатке случаев запиши неизвестное вместо выдуманного
«общего ядра».

| Наблюдение | Клиент / случай A | Клиент / случай B | Что повторилось / что неизвестно |
| --- | --- | --- | --- |
| Покупатель, плательщик и ситуация | | | |
| Купленный и принятый результат | | | |
| Текущий заменитель и цена перехода | | | |
| Данные, доступы, правила и интеграции | | | |
| Повторяемые действия и код | | | |
| Настройки, доработки и исключения | | | |
| Труд, обучение, поддержка и мощность | | | |
| Оплата, использование, повторный заказ | | | |
| Участие владельца и личных отношений | | | |

Пустые ячейки остаются неизвестными. Одна группа связанных организаций может
дать несколько сценариев исполнения, но ещё не независимое подтверждение рынка.

В выводе свяжи форму поставки с доказательством:

- Индивидуальная услуга: ценность и прибыль могут быть реальны, даже если
  рабочие правила каждого клиента существенно различаются.
- Стандартизированная услуга: повторяются результат и основной способ
  исполнения; настройки и исключения остаются управляемыми по качеству и затратам.
- Продукт с внедрением: повторяется ядро, а внедрение явно входит в предложение
  и экономику, не маскируется под бесплатное исключение.
- Самостоятельный продукт: дополнительно проверено, как клиент получает пользу
  без постоянного личного сопровождения; тариф сам по себе этого не доказывает.

Это варианты проверки, а не универсальная лестница развития компании.
Продолжать можно с той формой, которая подходит владельцу и покупателю.
