# Compatibility and one owning handoff

Project Start records known runtime/data/recovery constraints and links deployment
owner in the existing docs map. Unknown production setup does not block development.
Deployment is not a new mandatory coverage role; preserve old graph identities,
schemas and active receipts.

Task Delivery passes its deployment basis through existing plan/summary/handoff:
source/affected scope, native lane/runbook, check IDs/commands/subjects/environments/
prerequisites, actual results/original receipts, deferred checks and their trigger/
reason/consequence, changed toolchain/config/data/policy, risks and next action.
No required field is added to released task JSON. Tracked continuation uses its
supported summary/handoff interface; editing an unused template is insufficient.

Prepare fills real release-path gaps; release follows native owners without
reopening Project Start or rerunning unchanged development checks merely because
the skill changed. Permanent command/policy changes follow existing documentation-
impact maintenance. Use native contracts directly if extra mapping adds no value.

Production Audit reads the same quality/runbook/evidence and grants no rollout
authority. Optional companions apply to real gaps; absent Deployment does not
cause installation or bootstrap from a tiny task. Handoffs link one native journal
instead of copying mutable state. Reuse valid review/evidence; materially changed
contracts receive affected revalidation under host policy, not a new lifecycle
for every skill switch.
