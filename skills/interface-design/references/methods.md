# Adapted methods

These are task-sized methods, not a mandatory pipeline. Source identities and
licenses are in sources.lock.json. They borrow ideas, not upstream execution
requirements. Avoid importing arbitrary click limits, aesthetic presets or
unverified performance claims.

## Flow

Use when the question concerns task completion across states or screens.
Start with the outcome, entry context, role, relevant information and known
constraints. Organize navigation around the person's objects and actions, not
the database schema. Identify what must be visible before committing.

For a meaningful multi-step task, a compact table is often enough:

| State / entry | Person's goal | Action | System response / saved effect | Back, error, cancel or resume |
|---|---|---|---|---|
| Actual current state | Next useful outcome | Clear control | Observable change | Retained context and available recovery |

Include a state only when the task forces it: input validation, pending work,
no results, role limits, interruption, stale data or failed network. Trace an
invitation or handoff through the recipient when their action is in scope;
submission alone may be intermediate. State the owner of an out-of-scope end.

Minimize unnecessary decisions, duplicate entry and memory demand. Step count
alone is not the quality measure. Group related easy inputs; separate complex
decisions when it reduces load. Reveal secondary detail when useful without
hiding cost, consequence, privacy, authority or irreversibility. Keep context
when returning to a filtered list. Name why an action is unavailable and how
to proceed.

Acceptance: give a realistic goal without naming the intended control. Trace
entry, the main path, a recoverable error, back/change/resume and observable
completion. Automated and expert walks establish behavior; only real participant
observations establish human task results. Do not invent participants or uplift.

Primary basis: product-ux task-flow/IA/contracts; flow-audit's questions about
navigation and context. Exclude flow-audit's universal click/wizard limits,
weighted scores and unsupported conversion claims.

## References

Use when a material visual choice is open. Identify what belongs to this
product: its objects, materials, audience, real assets, vocabulary or distinctive
workflow. Let these facts supply the idea and content. A list of unsupported
features cannot become a product demo.

Choose one primary direction and name the traits to preserve: composition,
density, typography, color roles and media. Give a secondary source a specific
bounded role. Avoid averaging unrelated references into a generic compromise.
For a narrow existing edit inherit the current direction, without another
selection workshop. Use visual alternatives only when they resolve a real choice.

For imagery, record its job, available source, slot/crop and factual limits.
Use actual product/screens/assets when evidence matters; generated imagery
cannot establish a product capability or testimonial. For a showcase, connect
the main result to its real steps and important details.

Primary basis: Refero's styles/screens/flows and reference traits; Taste's
subject-led direction and page/app split; art-direction's image-role brief;
showcase's honest demonstration. Paid Refero tools are optional and are not
connected by this method. Upstream runtime/install/deployment commands do not
belong to the borrowed method.

## Interaction and visual finish

Use established components and predictable affordances in an operator screen.
Density follows the job; typography and alignment can provide hierarchy without
decorative containers. Keep the primary action and relevant information clear.

Motion must explain a state or serve a deliberate rare moment. Frequent actions
should remain responsive. Preserve input while saving; errors describe repair.
Test interruption and reduced motion where movement exists. Do not import the
Motion x/y/scale blanket prohibition from the motion snapshot: current official
Motion documentation differs, and the installed version must decide.

Use web-guidelines as focused questions about keyboard, labels, back navigation,
responsive text, feedback and stable layout. Validate uncertain numeric/library
claims against the relevant current primary documentation. These notes do not
certify WCAG conformance or human understanding.
