# AI Search Visibility

Help the requested site become a readable, trustworthy source for the selected
AI search products, then measure the result. Discoverability, reading, correct
facts, brand mentions, source citations, referrals and business outcomes are
different observations. No technique guarantees selection in an AI answer.

## Establish the actual question

Read the project's instructions, site/content owners, factual sources and prior
SEO/AI observations. Recover the site, market/language, user goal and relevant
products from that context. Clarify only gaps that materially change the work.
Keep company facts and evidence in the owning project, not this global skill.
Reuse applicable SEO evidence; run only missing checks. A simple page question
does not require a full-site audit or every AI product.

Use [provider-profiles.md](references/provider-profiles.md) for the selected
product's access and control differences. Refresh current primary documentation
before changing provider settings. An installed skill or an audit request does
not grant permission for account, robots/WAF, training-policy or public-site
changes. Continue fixes when already authorised; retain project release gates.

## Diagnose before recommending

Trace the relevant path: finding the URL → reading current facts → choosing and
citing sources → reaching the site → the user's actual business goal. Compare
concrete facts in source HTML, rendered output and a supported extraction path
when helpful. Observe missing content, stale caches, contradictory branch facts
and denied access separately. A changed User-Agent proves only that test request,
not access by the genuine crawler. An extractor's cache is not live truth.

Prefer important facts and useful ordinary links in accessible HTML; do not
declare that every AI bot is incapable of JavaScript or force a particular CMS.
Use available [SEO](../seo/SKILL.md) for affected URL, 404, schema, internal-link
or local-profile defects; if absent, perform the necessary scoped checks directly.
Tool absence reduces evidence, not the site's measured visibility to zero.

For content, make answers understandable with their subject, conditions and
attributable facts intact when excerpted. Compare actual cited sources for the
same question and market to find a useful content gap. Treat formatting ideas
as hypotheses; do not invent numbers, credentials, quotes or local experience.
No universal passage length, mandatory FAQ schema or /100 GEO score proves
citability. `llms.txt` and licensing files are optional, service-specific topics,
not a general search-admission gate; Google Search ignores `llms.txt`.

## Verify the outcome you can observe

Read [evaluation.md](references/evaluation.md) for prompt selection, saved
observations, fair comparisons and unavailable-tool cases. Use supported native
UI/API or supplied exports; do not equate a custom agent's response with the
consumer product. Exa/Firecrawl can test discovery or extraction but do not
demonstrate native ChatGPT, Alice or other products' citations.

Return affected URLs, observed failure/evidence, proposed/applied change and
verification, ordered by practical relevance. Distinguish official provider
guidance, local observations and experimental recommendations. State what was
actually checked and what remains unknown; save evidence and the next action
in the existing project report/task owner. Do not create another backlog,
controller or mandatory SEO-plus-GEO chain. Use the user's language.

Read [sources.md](references/sources.md) for primary sources and the rationale
for adapted or rejected ideas from external skills.
