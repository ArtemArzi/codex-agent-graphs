# Website Standards

Make the named website and critical visitor path reviewable against its actual
requirements. During website creation or changes, carry applicable standards
into the existing task plan and verify them before completion. Reuse the known
profile; do not require every integration or reopen settled decisions. This
skill selects checks; native project runners execute them. It creates no
controller, deployment engine or readiness score.

## Choose the requested action

- **Audit:** inspect the selected scope and distinguish defects from missing proof.
- **Prepare:** fill real gaps in existing project requirements, commands and fixtures.
- **Implement:** pass concrete changes to available Task Delivery/native owners.
- **Verify:** check the exact candidate and affected states, preserving valid evidence.
- **Operate:** use the existing incident/runbook owner or available Product Care.
  A note about later work does not register a schedule.

Read nearest AGENTS.md, the docs map, relevant quality/engineering/deployment
owners and current task handoff. Recover known decisions before asking questions.
Select goal, market, actual languages, Google/Yandex/both and measurement services
independently. Resolve only material unknowns. Do not enable every service,
invent multilingual pages or change design/content because this skill was selected.

Use [project-profile.md](references/project-profile.md) when a project needs its
first mapping. Existing documents can supply it without a new configuration file.

## Route only the affected capability

| Need | Owner |
| --- | --- |
| Technical crawl/index/URL correctness | Available seo; select its technical profile |
| GSC/GA4/Webmaster/Metrika identity and signals | Available web-measurement |
| Acceptance, repeats, delivery and recovery | Available reliable-leads |
| CTA/navigation/forms/mobile/error behavior | [technical-surface.md](references/technical-surface.md) |
| Release/readiness/incident decisions | Existing quality owner, Deployment, Production Audit or Product Care |

Read [evidence.md](references/evidence.md) when selecting, reporting or reusing
checks. Keep one requirement owner and one native release journal. Missing
companions are a capability gap: continue permitted work through project owners,
without installing tools or inventing completed checks.

Match actions to the current request and existing authority. Audit alone grants
no repair, account change, lead submission or publication. An already authorised
implementation continues through its owner without another permission ritual.
Use synthetic isolated fixtures for adverse tests; live/provider effects need
their applicable scope. Never send repository/customer data to an external
scanner merely because a checklist names one.

Report what works, observed defects, missing checks and the next concrete action
in the user's language. Separate publication, crawlability, indexing, impressions,
clicks, accepted leads, manager visibility and business effect. Use existing
readiness vocabulary; required unknown/not-run evidence cannot become PASS.

Read [examples.md](references/examples.md) for profile examples and
[sources.md](references/sources.md) when refreshing the standard.
