# Composio только для Codex Cloud

Этот профиль добавляет отдельный способ подключения для Cloud. На локальном компьютере сохраняются существующие MCP и plugins. Установщик переносимых скиллов не применяет этот профиль автоматически.

[Шаблон подключения](../profiles/connectors/composio-cloud.toml) содержит адрес сервера и имя переменной. Значение ключа, OAuth tokens, cookies и browser profile в Git и skills bundle не входят. Подключённые приложения остаются в существующем аккаунте Composio.

## Что переносится

Для Composio Connect используется `https://connect.composio.dev/mcp` и заголовок `x-consumer-api-key`. Нужен consumer API key из AI Clients / Connect Agents существующего аккаунта. Project API key Developer Platform и consumer key имеют разные договоры; не подставлять один вместо другого.

В шаблоне разрешены только `COMPOSIO_SEARCH_TOOLS` и `COMPOSIO_GET_TOOL_SCHEMAS`. Выполнение операций, управление соединениями и remote workbench не включены. Это ограничение конкретного MCP-клиента: сам consumer key может предоставлять более широкий доступ. Все разрешённые вызовы требуют обычного подтверждения клиента там, где этот режим поддержан.

Связь через тот же аккаунт позволяет повторно использовать приложения после проверки их статуса. При отзыве доступа или expiry потребуется штатная авторизация владельца. Перенос конфигурации не отменяет правила соответствующего сервиса.

## Подготовить Cloud environment

1. Выбрать одну среду и сохранить её текущую конфигурацию и состояние публикации. Не менять сразу все environments и не переносить локальные global configs.
2. В настройках среды запросить `COMPOSIO_CONSUMER_KEY` и разрешить точный destination `connect.composio.dev`. Сам по себе разрешённый домен не предоставляет доступ.
3. В Personal vault владельцу добавить **Network secret** с ключом `COMPOSIO_CONSUMER_KEY`, указать значение consumer key и ограничить применение выбранной средой. Не присылать ключ в чат. Личный network secret использует разрешённые destinations среды; одна запись vault без запроса из environment не доставляется в задачу.
4. Определить, где выбранный Cloud host настраивает MCP. Объединить только блок `mcp_servers.composio_cloud` из шаблона с поддерживаемой конфигурацией хоста. Не перезаписывать чужой config целиком. Если этот сервер уже существует с другой конфигурацией, сначала сравнить её с владельцем.
5. Проверить, что header получает placeholder из механизма network secret и реальный ключ подставляется для HTTPS destination. Не печатать заголовок, значение переменной, сетевые логи с credentials или содержимое vault.

OpenAI документирует `env_http_headers` для Codex MCP host и network secrets для Cloud. Их совместная работа в конкретной Cloud environment требует отдельной проверки. Изменение файла внутри VM не доказывает, что orchestration host перечитал его; secret substitution VM также не доказывает подстановку для внешнего MCP-клиента. Если нужные настройки недоступны, оставить подключение pending и передать точную диагностику владельцу.

Для этого маршрута установка Composio CLI и плагина не требуется. Не запускать обычный `curl | sh`: актуальный installer по умолчанию меняет shell и устанавливает обнаруженные plugins. Если MCP действительно недоступен и выбран CLI fallback, спроектировать его отдельно с закреплённой версией, отключёнными plugins/shell setup и отдельной проверкой авторизации.

## Проверить результат

- Из Cloud выполнить MCP initialize и tools/list. В действующем каталоге клиента проверить ровно два разрешённых meta-tools. На уровне сервера каталог может быть шире.
- Выполнить один ограниченный поиск инструментов и чтение схемы. Это проверка канала обнаружения; она не является выполнением операции в Instagram или другом сервисе.
- Сохранить проверенную подготовку, выполнить Publish/Republish и проверить доступ в новой Cloud задаче. Существующие задачи сохраняют своё состояние.
- Если нужны действия в приложении, сначала выбрать конкретные tools, проверить схемы и полномочия и отдельно расширить начальную allowlist. Методы multi-execute и manage-connections объединяют несколько действий; разрешение мета-инструмента само по себе не делает все вложенные действия разрешёнными.
- При неудаче не выдавать локальный CLI readback, наличие файла или Active в панели Composio за работающий Cloud connector.

Смена MCP-провайдера может менять имена, аргументы и ответы. Скиллу, который жёстко ожидает конкретный `mcp__github__...`, потребуется выбор доступной реализации и проверка результата. Composio не размещает собственный локальный сервер, Windows Chrome или localhost-службу автоматически.

## Обновить и отключить

Новая версия шаблона проверяется отдельно от обновления скиллов. Сравнить точную текущую запись MCP, сохранить прежние значения и применить только согласованную дельту. Ротация ключа выполняется в vault без пересборки скиллов.

Откат: отключить добавленный MCP и запрос секрета в выбранной среде, сохранить и опубликовать изменение. Проверить, какие существующие задачи ещё используют прежнее состояние; по действующим полномочиям обновить или завершить только затронутые задачи. Удалять только созданную этой установкой запись vault после проверки других потребителей. Существующие consumer key и OAuth grants приложений автоматически не отзывать.

## Лимиты

На публичной странице pricing 01.11.2026 Hobby включает 100000 tool calls в месяц, а Composio-managed OAuth имеет подлимит 20000 внутри общей квоты. Лимит конкретного ранее созданного аккаунта надо проверить отдельно. Собственные квоты Instagram и других API действуют дополнительно. Один запрос агента или пакет из нескольких upstream tools не следует считать одним оплачиваемым вызовом без проверки учёта.

Статус этого материала: шаблон для подготовки. Он не подтверждает подключение к конкретному Cloud аккаунту.
