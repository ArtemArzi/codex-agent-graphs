# Аудит локальных скиллов и стабильности графов, 6 октября 2026

Исправлены воспроизводимые дефекты Task Delivery, Project Start и установки.
Одиннадцать локальных скиллов получили узкие исправления инструкций и примеров.
Исходная работа пользователя сохранена. Сайт Indonesia и другие сайты в этот
аудит не входят. Состояния старых запусков, подписи выпусков, секреты и профили
не мигрируются и не переписываются.

Независимая приёмка кандидата и фактической установки/публикации пройдена.
Скиллы в WSL и Desktop сверены с каноническим исходником; повторная установка
не меняет файлы. GitHub main совпал с опубликованным кодом. [Итог и доказательства
синхронизации](SYNC.md) отделяют локальные тесты, установку и фактический push.

## Почему появлялись остановки

| Наблюдение | Причина | Исправление / граница |
|---|---|---|
| Task Delivery повторял ошибку read-only admission lock | Ответ предлагал повторить ту же команду без новых фактов | Классификация сбоя и максимум одна ограниченная попытка ремонта; затем разрешённая работа нативно с сохранением оставшихся проверок |
| Project Start после сбоя требовал вернуть созданные документы к исходному состоянию | В контроллере не было операции degradation, оставались abandon/recover | Добавлен control-degrade, документы и общая authority сохраняются; completion контроллера блокируется |
| Разрешённая область плана могла расшириться без изменения хэша | Хэш считался по одному участку, scope извлекался из всего файла | Scope связан с приёмкой и проверяется при работе, checkpoints и завершении; новые планы имеют один scope внутри хэшируемого контракта |
| Полная установка конфликтовала с отдельным provider profile | Установка навыков была связана с общей модельной конфигурацией | --skills-only обновляет навыки/runtime, сохраняя конфигурацию, роли, провайдеры и глобальные правила |
| Запрос точного digest для Indonesia | В показанном чате это граница website-neutral-v2 и связанного application/page-map контракта | Это не доказанный дефект Task Delivery. Повторный ритуальный запрос устраняется инструкциями, настоящая авторизация выпуска сохраняется |

Исходный воспроизводитель расширял `src/app.py` до `src` после implement
admission, затем принимал новый файл и завершение при неизменном digest.
Новые регрессии отклоняют это расширение, а обычные правки файлов, новые файлы
в разрешённом каталоге и действительные scope amendments проходят.

## Изменения

**Task Delivery 3.9.1.** Сохранены старые алгоритмы digest и точные identities,
включая исходный graph 3.9.0. Никакого переписывания старых state.json. Scope
проверяется по подлинной сохранённой области решения, а не по хэшам изменяемых
рабочих файлов. Неоднозначный старый packet или неизвестный graph остаётся
непринятым: сохраняется состояние и handoff для разрешённой нативной работы.

**Project Start 3.5.1.** control-degrade фиксирует здоровье управления отдельно
от результата работы. Остаются pending decisions, obligations, receipts,
active marker и общая project authority. Нативное продолжение не превращается
в ложный controller PASS. Даже запуск без verify не может завершить degraded
контроллер. Для недоступного/повреждённого state handoff сохраняется вне него.

**Установка.** Все среды проверяются до записи. Есть блокировка установщика,
проверка исходных и текущих байтов, staging, резервные копии заменяемых каталогов,
полная сверка и идемпотентность. При сбое во второй среде собственные изменения
откатываются; обнаруженные чужие параллельные изменения сохраняются и сообщаются
как конфликт. Это не гарантия атомарности против любого стороннего процесса,
который игнорирует блокировку. Обычная полная установка остаётся строгой.

| Скилл | Исправлено |
|---|---|
| skill-stocktake | Текущий host, точные версии/корни, честное покрытие, неизвестная usage, stdlib inventory, без обязательных пачек агентов |
| token-budget-advisor | Убраны отсутствующая зависимость и выдуманная точность; уже выбранная длина не вызывает вопрос |
| ecc-tools-cost-audit | Подтверждённый путь проекта вместо отсутствующего sibling |
| agentic-engineering | Модели и делегирование принадлежат host policy; переход стадии не требует нового чата |
| blueprint | Соразмерная приёмка вместо strongest-model; память меняется только по просьбе |
| prompt-optimizer | Нет обязательного /plan и смены моделей для каждой средней задачи |
| security-scan | Проверка доступности без скачивания npx; installs, --fix и платная отправка отдельно авторизованы |
| continuous-agent-loop | Router использует существующий autonomous-loops; нет обязательного стека и выдуманных команд |

Модельные роли, ручной root effort, auth, MCP, глобальные AGENTS, изолированные
профили и disabled rules остаются неизменными. Новые текущие skill bodies хост
обнаруживает автоматически; это не обновляет уже выданные инструкции активным
агентам и не является основанием их перезапускать.

## Доказательства и оставшиеся ограничения

Полный `python3 scripts/check_all.py` прошёл: 453 теста в девяти наборах,
metadata validator для всех 29 устанавливаемых skill trees и dev-policies,
четыре graph contracts, Python/TOML проверки и согласованность 14 Claude agents.
Отдельные изменения покрывают scope tampering, старые identities/digests,
degraded completion, сохранность obligations, EROFS, двухсредный rollback,
параллельные правки, отсутствие модели/429/network и точные inventory aliases.
`git diff --check` пройден. Публичный GitHub проверяется после публикации. GitHub Actions workflow в этом репозитории не настроен; CI PASS не заявляется.

Provider-owned/system caches не редактировались. Среди них есть upstream
конфликты: strongest-model/обязательный workflow в Superpowers и расхождение
google-drive/google-docs о создании Docs. Приоритет host/user инструкций
действует, но это не исправление исходного плагина. Через доступные инструменты
нет поддержанного обновления всех установленных plugin releases; поэтому
«все плагины теперь самые новые» не заявляется. Их API и интеграции требуют
проверки по конкретному следующему заданию. Скиллы из общих .agents/Claude,
которые не имеют доказанного дефекта, сохранены.

Старый контроллер может требовать named acceptance-role receipt там, где новая
host policy разрешает bounded reviewer. Такой запуск деградируется честно:
роль не переименовывается, схема не ослабляется, obligations не очищаются.
Project Start schema сама по себе не доказывает независимость reviewer;
настоящая приёмка подтверждается отдельной историей/результатом агента.

Основные проверенные источники:
[Codex skills](https://developers.openai.com/codex/skills/) объясняет загрузку и
обнаружение изменений; [Gemini deprecations](https://ai.google.dev/gemini-api/docs/deprecations)
подтверждает выключенные Gemini 2.0, а [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)
требует смотреть лимиты конкретного аккаунта. Копии лицензий/NOTICE исходных
адаптаций сохранены. Секреты, полные конфиги и сырые чаты в публикацию не входят.
