# Лёгкая проверка качества навыка

Читай при создании или изменении навыка. Для обычного применения выполняй его
собственную инструкцию. У каждого навыка сохраняется существующий владелец
метода, состояния и результата.

## Сначала найти конкретный пробел

Проверь, понятно ли из SKILL.md и его условных ссылок:

- когда навык подходит и как отличается от соседних;
- откуда взять исходный контекст и какие существенные неизвестные остаются;
- какой полезный результат нужен и что подтверждает его готовность;
- как продолжить при отсутствии данных, инструмента или дополнительного навыка;
- где сохранить результат и кому передать следующий шаг, когда это применимо.

Это вопросы для автора, а не обязательные заголовки, анкета или новый файл
контракта. Короткий вход может передавать метод другому навыку; справочник может
оставаться справочником. Прочитай решающую ссылку до объявления пробела.
Существующие достаточные инструкции не дублируй. Сохраняй права, источник
фактов, лицензии, принятые решения и ограничения старых запусков.

## Добавлять обвязку по её назначению

| Потребность | Достаточное средство |
| --- | --- |
| Показать отдельный навык в интерфейсе | Поддержанные поля agents/openai.yaml; отсутствие карточки само по себе не дефект метода |
| Уточнить вход и выход | Короткое условие в существующем SKILL.md или его профильном reference |
| Повторять вычисление или проверку файла | Небольшой исполняемый helper с настоящими проверками |
| Описать повторяемую процедуру | Существующий workflow, если отдельный рецепт действительно помогает и имеет читателя |
| Продолжать работу после перерыва | Существующий владелец задачи и его состояние |
| Программно контролировать переходы и повторы | Обоснованный существующий граф с его runtime и проверками |

Не добавляй YAML ради расширения файла и не вводи собственные state/runner/graph
для каждого навыка. Прочитай активный skill-creator перед изменением упаковки;
writing-for-agents помогает определить условия чтения и границы завершения.
Политики хоста и проекта сохраняют приоритет.

## Проверять поведение, а не совпадение слов

Для изменённого поведения выбери полезный пример: обычный запрос, недостаток
данных, ошибочную предпосылку или недоступный инструмент. Число случаев зависит
от изменения; новый полный набор не требуется каждой правке текста.

Небольшой репозиторный helper подготавливает изолированные синтетические задания:

```sh
python3 scripts/skill_cases.py list
python3 scripts/skill_cases.py check
python3 scripts/skill_cases.py prepare blueprint-existing-plan --output /tmp/blueprint-case
```

Передай свежему исполнителю только подготовленный TASK.md, его входы и указанный
навык. Смысловые критерии остаются в tests/fixtures/skill-cases/cases.json для
последующего разбора. Helper не вызывает модель, не выставляет оценок и не
запускает код из fixture. Он отказывается перезаписывать существующую папку.
Задания разрешают только действия внутри своей временной папки.

Результат оценивай по выполненной задаче и наблюдениям: использован ли настоящий
контекст, сохранён ли владелец плана, видны ли неизвестные и фактические проверки.
Не оценивай смысл по наличию слов, заголовков или длине ответа. Скрипт может
проверить арифметику или структуру; фактология и полезность требуют своих
источников и проверки. Исполнитель не должен заранее получать ожидаемый ответ.

У маркетингового пака также есть собственные
[сценарии](../products/marketing-cycle/validation/SCENARIOS.md) и
[свидетельства прогонов](../products/marketing-cycle/validation/FORWARD-RESULTS.md).
Используй существующего владельца случаев, не копируй их в новую очередь.

## Закончить изменение

Выполни относящиеся проверки и обязательный scripts/check_all.py перед коммитом.
Сохрани у текущей задачи: изменённое поведение, фактические результаты, ограничения
проверки и следующий шаг. Валидация структуры, сценарный прогон, установка,
обнаружение в интерфейсе и работа на реальном проекте доказывают разные вещи.
Проверку и независимый обзор выбирай по действующей политике, без нового
обязательного controller или второй системы приёмки.
