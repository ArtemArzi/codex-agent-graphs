# Software Factory

Отдельный скилл для Codex, который работает через Task Delivery и выбирает
обычную, последовательную или параллельную разработку по зависимостям задачи.
Маленькую связанную задачу root выполняет напрямую. Независимые части получают
отдельные ветки/worktree и пакеты контекста. Дашборд и отдельный controller не нужны.

## Использование

После штатной установки и открытия нового чата:

> $software-factory Выполни задачу через Task Delivery. Выбери режим по
> зависимостям. Для параллельных частей подготовь отдельный контекст, затем
> собери общий кандидат, прогони проверки и независимое ревью по политике.
> Работай в отдельных ветках, без переноса в main и push.

Без установки можно явно попросить прочитать `skills/software-factory/SKILL.md`
из открытого репозитория. Имя в каталоге и frontmatter — `software-factory`.
Установщик включает папку скилла целиком, со скриптом и references. Сначала
просмотри его план; применение установки требует соответствующего разрешения.

```bash
python3 scripts/install.py plan --skills-only --all
python3 scripts/install.py install --skills-only --all
python3 scripts/install.py verify --skills-only --all
```

`--skills-only --all` обновляет все поддерживаемые скиллы в найденных целевых
профилях, а не только Software Factory. Он сохраняет настройки моделей, roles,
config и глобальные политики; локальный drift обрабатывает штатный установщик.
Публикация в GitHub сама по себе установку не запускает.

## Контекст и ветки

Root закрепляет общий контракт до запуска зависимых исполнителей. Каждый
получает цель, точный base commit, источники, рабочую папку/ветку, разрешённые
файлы, исключения и команды проверок. `prepare --context FILE` сохраняет снимок
текста и его SHA256 в brief; root проверяет смысл и источники. Полный чат,
секреты и активное runtime-состояние TD/PS в пакет не переносятся.

Скрипт `skills/software-factory/scripts/factory.py` готовит worktree, показывает
status и проверяет интеграцию; агентов запускает root через native Codex tools.
Каждый исполнитель тестирует свою часть и возвращает отдельный коммит. Root
сверяет реальные диффы, объединяет точные SHA в новую integration-ветку и
проверяет общий результат. Проверка свежести не заменяет независимое ревью.
Подробные команды: [helper-usage.md](../skills/software-factory/references/helper-usage.md).

Максимум два одновременно пишущих агента и два writing job в одном workspace.
Зависимые части идут последовательно или волнами от проверенной базы. Разные
файлы не гарантируют независимость: общие API, БД, порты и output требуют общего
решения либо изоляции. Worktree не является sandbox прав доступа.

Task Delivery сохраняет свой жизненный цикл и правила проверки. Project Start
обслуживает канонические документы там, где этого требует выбранный режим.
Результат sibling controller нельзя выдавать за receipt main или копировать как
активное состояние. Никакой фиксированной цепочки из семи агентов нет.

## Проверенная основа и дальнейшие границы

Проверен и обмен между native агентами: root→исполнитель→root и два исполнителя
друг другу в обе стороны, с ответами на отдельные идентификаторы. Завершённый
исполнитель получил сообщение из очереди через `followup_task` и сохранил
предыдущий контекст. Несуществующий адрес вернул явную ошибку. Это ограниченный
функциональный тест, а не гарантия отсутствия задержек или восстановления после
падения. `send_message` сам по себе не запускает завершённого агента.
Инструменты для создания/связи отдельных пользовательских чатов в проверенном
наборе не были доступны; root-to-root между такими чатами не тестировался.
Native agent, Git-ветка и пользовательский чат — разные объекты.

10 октября 2026 выполнен реальный native-прогон двумя агентами на независимых
расширениях отчётов: фильтр сводки и check-режим сравнения. Каждый получил свой
снимок контекста и изменил только назначенные файлы. Общий кандидат прошёл
536 тестов отчётов, 17 архитектурных/offline integration проверок, свежий
сценарный runner (12 pass) и 30 CLI проверок. Независимое ревью: PASS.
Код этого приложения остаётся в его экспериментальных ветках и не входит в
репозиторий навыков. Эти числа относятся к тому прогону, а не к всему текущему
validation gate репозитория.

После прогона скилл переименован из factory-pilot, helper перенесён внутрь папки
скилла. Его 21 тест включает полный Git-цикл после копирования только этой папки.
Проверки helper теперь входят в общий `python3 scripts/check_all.py` через
`tests/test_software_factory.py`. Установка полного нового дерева проверяется
временным профилем, без обновления действующих профилей пользователя.

Не проверены: полный native-прогон уже под новым именем после установки,
автообнаружение свежим Desktop/CLI-чатом, tracked TD→PS, четыре одновременных
агента, восстановление после падения, provider E2E, выполнение нового workflow
в Claude и выигрыш времени/стоимости. Это исходная рабочая версия для дальнейших
изменений отдельными коммитами. Скрипт сам не пушит, не переносит в main и не
деплоит; эти действия определяются разрешением текущей задачи.
