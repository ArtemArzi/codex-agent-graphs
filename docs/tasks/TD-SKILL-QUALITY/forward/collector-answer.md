Рабочая готовность не подтверждена. В collector.py воспроизводятся сбои обработки ошибок; до рабочего запуска нужны исправления по отдельному поручению и повторная проверка. Сейчас код и структура оставлены без изменений.

Подтверждено локально:

| Проверка существующего кода | Наблюдение и следствие |
|---|---|
| fetch: HTTP 200 с items=[] и HTTP 500 | В обоих случаях []. Нельзя отличить пустой источник от ошибки получения. |
| HTTP 200 с одной синтетической записью -> store -> чтение памяти заглушки | Одна запись совпала с исходной; store вернул 0. Это только сценарий с in-memory storage, не живая доставка. |
| Повтор того же входа с той же save-заглушкой | Стало две одинаковые записи. В store нет дедупликации; возможные гарантии настоящего storage неизвестны. |
| save возвращает False | store возвращает skipped=1; отдельного статуса failed и идентификатора не даёт. Нельзя считать этот счётчик количеством уже существовавших записей. |
| save выбрасывает OSError | Исключение выходит наружу. В показанном коде нет обработки и отчёта о частичном результате. |

Первое неверное допущение: пустой список означает успешное отсутствие данных; skipped означает безопасный пропуск. Код стирает различие между результатом и ошибкой. Успешный вызов save также сам по себе не доказывает долговечное сохранение.

Источник, целевое хранилище, объём, частота и допустимая потеря данных пока неизвестны. Новый стек и AI для этой задачи не требуются.

Предусмотреть ограниченные повторы с задержкой и общим бюджетом, наблюдаемый окончательный отказ; без бесконечного цикла. Для timeout/429 и некорректного JSON также нужны отдельные результаты.
