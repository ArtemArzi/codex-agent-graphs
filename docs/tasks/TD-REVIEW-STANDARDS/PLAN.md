## Основание и путь применения

Project Start SKILL -> documentation-contract -> роль engineering_standard или
ENGINEERING template -> Task Delivery SKILL и planning-contract/testing-and-review
-> фактическое review. Существующий must-read сохраняется. PLAN-REVIEW/CODE-REVIEW
являются записями результатов среди legacy-совместимых шаблонов; активный маршрут
читает references и не зависит от создания этих файлов. Контроллер не проверяет
семантику. Стандарты остаются у проекта, review содержит их применение.

Первичные источники сверены 2026-10-21:
[Anthropic](https://code.claude.com/docs/en/code-review-customize),
[Google](https://google.github.io/eng-practices/review/reviewer/looking-for.html),
[Rust RFC](https://github.com/rust-lang/rfcs/blob/master/0000-template.md).
Это адаптация критериев, не перенос процесса. Запрет комментариев является
отдельным решением пользователя, включая docstrings/JSDoc и закомментированный код.
Старые лицензии/директивы сохраняются; массовое удаление вне задачи не требуется.

## План и приёмка

1. Уточнить существующий Project Start guide: связные обязанности, интерфейсы,
   рост относительно baseline, обоснованные швы и фактический способ контроля.
2. Доработать текущие Task Delivery references и routing: стороны плана/кода,
   правило -> место -> доказательство -> последствие, дефект/нарушение/совет.
   Сохранить соразмерность; комментарии запрещены в новом коде.
3. Дополнить два шаблона применения стандартов, сохранив машинные поля.
4. Подготовить три случая через существующий skill_cases: варианты плана/кода,
   maintenance engineering guide и маленькая кодовая правка. Свежий исполнитель
   получает TASK и входы без rubric. Проверять фактические решения и код.
5. Выполнить unittest подготовки, quick_validate навыков, ссылки, diff --check
   и scripts/check_all.py; получить один независимый block_reviewer результата.
6. Сохранить точный кандидат коммитом, отправить в GitHub и подтвердить SHA.
   Интегрировать локально с сохранением чужих правок. Установить только два
   изменённых навыка в WSL/Desktop существующими installer helpers: preimage,
   drift, backup, readback, повторный no-op. Модели/профили сохранить.

Это ограниченная правка инструкций/шаблонов и synthetic fixtures без новых
подсистем или внешних бизнес-эффектов. Native skill-only, один auxiliary result
review без whole-plan/whole-result пары. Установка ограничена двумя проверенными
каталогами с резервными копиями; иные различия install plan исключены.

Готовность: Project Start материализует правила, обе стадии получают критерии,
плохой план/код отклоняются с основаниями, хороший не требует пустого дробления,
маленькая правка сохраняет поведение и не добавляет комментарии.
