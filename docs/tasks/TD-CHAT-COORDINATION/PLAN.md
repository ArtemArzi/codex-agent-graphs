## Решения и область

- Новый chat-coordination: короткий автоматически доступный SKILL.md, UI metadata и условные references по сообщениям/восстановлению и сценариям. Никакого scheduler, централизованного реестра, controller, новой роли, автоматического мониторинга или скрытого shell API.
- Общий protocol: bounded relevant discovery по known IDs/ресурсам; partial visibility и tool fallback; stable task/resource identity; explicit direct-human messaging scope; message/ACK/agreement/effect отдельно; старые ответы, новые требования, неизвестный owner, конфликты и безопасная независимая работа.
- Прямое человеческое разрешение на переписку не создаётся skill. Другие user-owned чаты не создаются; чужие задачи не останавливаются. В этой задаче разрешён обмен с чатом упаковки; реальный пилот двух новых пользовательских чатов остаётся отдельным запросом.
- Узкие входы из policies/orchestration.md, TD (включая quick/resume), PS, Factory, Deployment и Product Care. Не превращать простые правки в обязательный обход чатов. Роли/модели/review thresholds/graph identities не менять.
- Factory: точечный reconcile-before-redispatch в существующем routing reference; committed result/actual integration не повторяются из-за потерянного сообщения, частичная работа сохраняется; новый писатель не выдаётся при неизвестной активности старого. Helper/API/schema без изменения.
- Текущий install.py: явно добавить skill в managed default (38→39) по новому поручению. Условный companion не делать обязательной фазовой зависимостью всей TD/PS. В dependency declarations указать optional только там, где реально используется; fallback остаётся.
- Отдельная совместимая копия preview fddc28d: перенести нашу точную дельту, добавить новый skill в каталог и обновить generated docs/tests; проверить optional/required closure и native bundle содержание. Его опубликованная основа/архивы не заменяются этим тестом. Передать отдельный commit/patch владельцу упаковки.

## Порядок реализации

1. Получить свежий whole-plan PASS для инженерной реализации. Прежний research PASS не заменяет его: внедряются новые межпроцессные контракты и общий policy routing.
2. Root реализует skill, references, условные входы и инсталляционную декларацию. Не делегировать мелкие зависимые правки и не добавлять executable decision model вместо инструкций.
3. Проверить skill validator, реальные относительные ссылки/metadata, targeted installer и неизменённый Factory suite; до commit выполнить весь python3 scripts/check_all.py по AGENTS.md. Логи с командами/exit сохранять в evidence, не в тексте навыка.
4. Провести bounded forward-проверки свежих агентов по содержательным сценариям: нет пересечения/простая правка; неизвестные полномочия и позднее сообщение; общий ресурс/partial visibility; commit либо интеграция уже выполнены при потерянном ответе. Заморозить ожидаемые действия до прогонов; фактические tools/файлы важнее намерений. Не выдавать child fixtures за root-to-root pilot.
5. Проверить совместимость с кандидатом упаковки в отдельной копии. Полный gate повторять после смысловых исправлений/изменения объединённого кандидата только по необходимости; native bundles пересобрать, если их состав меняется.
6. Установить принятые source bytes штатным manifest-aware skills-only installer в два homes с preimage/backups/verify и повторным no-op. Для глобального входа отдельно обновить только свой managed orchestration block через существующие installer primitives с backup и readback; остальные байты AGENTS, config, модели/профили/роли и прочие деревья сохранить. Проверить это сначала на временной копии. Не добавлять новый installer flag/runtime ради одной активации.
7. Свежим WSL CLI и Windows Desktop runtime проверить actual catalog и prompt presence. Если выполним bounded model turn — отдельно зафиксировать именно поведение, не смешивать с discovery. Существующие открытые контексты не считать автоматически перечитанными.
8. ДРУГОЙ свежий task_result_reviewer принимает весь результат по источникам/диффам/evidence/фактической установке. Исправления — тому же reviewer. До этого не объявлять доставку завершённой.
9. Сохранить узкие проверенные commits, перенести только их fast-forward в чистый канон с повторной проверкой source/remote, выполнить ранее разрешённую публикацию сегодняшних skills без force. Проверить GitHub exact head. Не включать preview упаковки и не менять серверы/данные. Передать packaging-владельцу точную дельту совместимости и границы тестов.

Установка является ограниченной поставкой инструкций: результат не объявляется проверенной автоматической координацией самостоятельных чатов. Предшествующий research pilot остаётся критерием такого более сильного утверждения. В рамках уже данного права можно проверить реальный ограниченный обмен с существующим чатом упаковки на общей задаче и получить его scope/base; это не заменит весь отказный пилот и не требует создания новых чатов. Эту границу явно сохранить в итоговом evidence и документации.

Активация policy выполняется отдельно от skills-only: не вызывать full install или agents_with_policy(), которые могут переписать остальные managed blocks. Использовать существующий skills_install_lock для обоих homes в стабильном порядке, fresh source/target preimages, замену ровно одного валидного orchestration block, backup и проверку всех внешних байтов; этот lock координирует только сотрудничающих установщиков, не произвольных редакторов. Непосредственно перед записью повторно сверить preimage. Native verify/discovery failure, ошибка второй home или несовпадение protected readback останавливают публикацию и запускают owned-byte rollback по docs/INSTALLATION.md:162–180. Восстанавливать только совпадающие с нашим записанным manifest/block байты, сохраняя неудачный результат в backup/quarantine, без удаления чужой работы; если target уже изменился независимо, сохранить оба состояния и остановить только конфликтную часть. После rollback подтвердить preimage readback. Сначала проверить такую узкую замену, отказ второй home и повторный no-op на временных копиях.

## Приёмка и проверяемые риски

| Риск/требование | Проверка и критерий |
| --- | --- |
| Навык не доступен или установлен частично | validator, manifest+reference readback, свежие оба native catalogs, одно имя без duplicate/error, prompt presence |
| Skill сам выдаёт messaging/production полномочия | read-only independent review и forward case: peer request без прямого human grant не вызывает отправку |
| Idle/timeout принят за право ресурса | case с неизвестным живым владельцем: нет нового writer/lock deletion; независимый участок продолжается |
| Общий API/runtime пропущен по разным cwd | case по resource identity: изоляция/очередь; наблюдение не называется lock |
| Потерянный ответ повторяет уже сделанную работу | реальный scratch Git commit/интеграция + fresh agent: inspect actual state, выполнить только недостающее |
| Новый глобальный trigger тормозит мелкие задачи | negative control: простая независимая правка без обхода чатов/Factory/нового интервью |
| Пересечение с packaging | отдельная интеграционная копия, frozen fddc28d/его архивы неизменны; каталог57, closure, bundle/targeted checks |
| Установка меняет чужие настройки | preimage→backup→readback; разрешена дельта своих skills + только orchestration block; повтор без новых backups/bytes/mtime |
| Gate PASS принят за реальную координацию | отчёт разделяет structural/tests, model fixtures, native discovery, реальные чаты и production; последние два не выдумываются |

Документ качества отдельным владельцем в этом repo не задан: применяются AGENTS.md, docs/WORKFLOWS.md, TD testing-and-review.md и установленный skill-creator. Runtime checks и графы прежних версий остаются без изменений. Состояние controller для этой skill-only/native реализации не создаётся только ради review.

## Остановки

Не затирать канонический или установленный drift. При обнаружении новых чужих изменений — сохранить их, пересобрать интеграцию от проверенной версии. Недоступный обязательный review не заменять self-check. Операции, требующие нового user-owned чата, production либо нового права, не выполнять; остальную поставку продолжать. Поддержка всех спящих чатов и принудительное взаимное исключение не входят в обещанный результат.
