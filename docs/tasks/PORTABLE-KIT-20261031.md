## Требуемый результат

Один canonical источник стандартов, ролей, скиллов с рекурсивными обязательными зависимостями, вложенными ресурсами, runtime и явно выбранными знаниями. Повторяемая переносимая сборка, установка, обновление, проверка, откат и инструкция для новых улучшений. Установленные личные источники дополняют canonical, но не заменяют более новые canonical workflows. Новые canonical скиллы включаются при следующей сборке. Конфликты разных ресурсов требуют явного выбора.

MCP, auth, credentials, активные графовые runs и рабочие глобальные установки исключены. Хостовые возможности плагинов нельзя выдать за установленные переносом файлов. Избранные знания private; автоматической публичной публикации нет. Поддерживаемая установка Linux/WSL; Cloud требует отдельного реального пилота. Произвольные package install/hook команды не исполняются из скиллов. Манифест сохраняет lockfiles/requirements и doctor сообщает внешние prerequisites.

## Архитектура и план

1. Снимок native skills/list текущего выбранного хоста, только enabled entries, discovery errors блокируют сборку. Metadata-only app-server без model/MCP calls. Canonical исходники и explicit profile разрешают пути/приоритеты; прочие plugin namespaces проецируются в уникальные имена с сохранением соседних ресурсов и лицензий. Неразрешённые обязательные зависимости блокируют сборку.
2. Самодостаточный bundle с четырьмя Python stdlib bootstrap файлами, payload и проверяемым манифестом: все файлы, режимы, hashes, provenance, зависимости, внешние пути и capabilities. Нельзя включать symlinks/hardlinks/special files, секреты и приватное runtime state. Build не перезаписывает существующий output и не удаляет неизвестные bytes при ошибке. Проверяется изменение источников во время снимка и пересечение output с любым input.
3. Установка только в отдельный явно указанный CODEX_HOME, без adoption непустого чужого home. Mutable auth/sessions/cache остаются в стабильном home. `.portable-kit/releases/<id>` содержит неизменный payload, `current` переключается одной ссылкой. Корневой `skills` является настоящим стабильным каталогом: native Codex пишет `.system` туда. Каждая принадлежащая набору верхняя skill-папка является ссылкой через current. Системные, неизвестные и пользовательские файлы не заменяются и не удаляются.
4. Один lock на plan/install/verify/rollback/run/retire, descriptor anchors и exact hashes защищают от drift/подмены родителей. `run` держит lock до завершения дочернего процесса. Прямой запуск CODEX_HOME вне wrapper не получает эту блокировку. Неполная transaction после crash блокирует дальнейшие изменения и сохраняет доказательства. Ошибка не авторизует удаление foreign bytes.
5. Идемпотентное обновление и rollback сохраняют mutable home и старую версию. Максимум 3 поколения и 1 GiB payload. Явный `retire --target HOME --release ID` может убрать только полностью проверенное поколение, которое не current и не previous, под тем же lock. Перед удалением сохранить transaction intent и использовать quarantine; crash остаётся видимым. Удалять только доказанно принадлежащие retired поколению ссылки, более не используемые ни одним retained поколением; unknown/drift/busy блокируют. Обновление A-B-C, retire A, затем D должно работать без нового home.
6. Проверки настоящей файловой системы: перенос bundle без source, рекурсивные зависимости, ресурсы/плагины/knowledge allowlist, tamper, конфликты, symlink и secret rejection, idempotence/update/rollback/retirement, drift/lock/crash preservation. Реальный native discovery в изолированном HOME с текущим Codex, затем verify; никаких изменений глобальных установок. Полный `python3 scripts/check_all.py` перед commit.
7. Fresh whole-result acceptor, отличный от автора и plan acceptor. После PASS сохранить исходники локально в Git, безопасно fast-forward canonical main при неизменном baseline. Публикация не подразумевается. Очистка других деревьев только после точной проверки истории/dirty/ignored; уникальные изменения и история сохраняются в проверяемом recoverable archive. Никакого blanket force/prune неизвестных ресурсов.
