# ЗА КРАЙ: пешие экспедиции

## Status and authority

An original fictional landing-page prototype. The user explicitly approved a striking unusual landing and delegated topic, visual direction and source selection. The earlier authorized frontend-only constraint carries forward. All routes, distances and programme details are illustrative; no real operator, bookings, tickets, testimonials or outcomes are represented. Generated hero imagery depicts an invented place.

## Platform

Web, responsive desktop/mobile, keyboard and reduced-motion support.

## Stack

Delegated within the accepted static-prototype stack: HTML, CSS and small vanilla JavaScript. Local OFL fonts, original generated landscape plates and locally vendored Three.js0.186.1. scene.js is a separate progressive enhancement; app.js never imports it. No framework, backend, analytics, remote fonts, live map or account integration. Python's existing static server is sufficient.

## Person and task

A person considering a short walk outside ordinary city routes should understand the offer, compare two illustrative routes, choose a pace, save one local plan, reopen it and download a readable note. Primary outcome is a genuinely working local plan; it does not confirm a real excursion or booking. No personal information is requested.

## Surface brief

Mode: Persuade, with a small Operate flow in the route planner. One primary action: choose a route. Visual world chosen by the agent under explicit delegation: a kinetic expedition poster with a living cloth sculpture, layered Unbounded Cyrillic typography, mineral scenery, ink-green text and a rust-orange action. The prior static version was explicitly rejected as too ordinary. One strong visual gesture, restrained navigation and route metadata.

Reference roles: teenage engineering EP-133 for the relationship between object, large type and technical annotation; Field Notes for field-guide vocabulary and compact material detail; Fondation Cartier for an exhibition-led composition. These are references to traits, not copied layouts or source photographs. Field Notes returned a browser403, so only accessible primary-site content was used and no visual-fidelity claim is made for that page.

## Behaviour and limits

Flow: landing → route comparison → planner → pace → save → confirmation → reopen/edit or download. Native dialog handles modal focus and Escape; errors preserve choices. Storage is limited to one non-personal record under this demo's own key. Corrupt or blocked storage must not prevent browsing or downloading. The site states its fictional status and local-save scope.

## Acceptance

Real rendered desktop/mobile inspection; no overflow or lost action; meaningful keyboard focus; route/pace and confirmation stay consistent; local save survives reload; blocked storage has a recoverable message; downloaded note matches the selected route and is marked as an exercise. Live motion must visibly change, have a usable pause and respect system reduced motion. Offscreen, hidden-document and modal pauses must compose with user intent. Module/WebGL/context-loss fallback must leave the product flow usable. Record lab observations separately from user usability or production effects.
