# Улучшение и автоматизация бизнес-процессов

Версия продукта: **1.1.0**. [Состав и версии источников](pack.json).

Общий business-work также маршрутизирует доступный отдельный
[пак бизнес-модели](../business-model/README.md). Его три специализированных
навыка не устанавливаются этим паком автоматически. При установке нескольких
паков используй одну проверенную версию репозитория для общего business-work.
Один вход: [`$business-work`](../../skills/business-work/SKILL.md).

Пак помогает войти в бизнес с рассказа клиента, восстановить реальную работу,
выбрать улучшение, спроектировать будущий процесс, подготовить реализацию и
проверить применение людьми. Онлайн, офлайн, смешанные услуги и внутренние
процессы входят в одну область. Это инструкции для агента, без нового сервера,
runtime, графа или трекера задач.

## Структура и повторное использование

| Часть | Канонический источник |
| --- | --- |
| Общий вход и выбор следующего шага | [business-work](../../skills/business-work/SKILL.md) |
| Подготовка интервью, самостоятельной анкеты и следующей встречи | [customer-research-prep](../../skills/customer-research-prep/SKILL.md) |
| Контекст с нуля и текущая работа | [Руководство](../../skills/business-work/references/context-and-current.md) |
| Выбор изменения и будущий процесс | [Руководство](../../skills/business-work/references/future-process.md) |
| Внедрение с людьми и результат | [Руководство](../../skills/business-work/references/adoption-and-effect.md) |
| Продукт, сегмент и предложение | [NMT chat](../../skills/nmt-chat/SKILL.md), [diagnose](../../skills/nmt-diagnose/SKILL.md), [market research](../../skills/nmt-market-research/SKILL.md), [interviews](../../skills/nmt-analyze-interviews/SKILL.md), [value proposition](../../skills/nmt-craft-value-proposition/SKILL.md), [requirements](../../skills/nmt-product-requirements/SKILL.md), [go-to-market](../../skills/nmt-craft-go-to-market/SKILL.md) |
| Ожидания и факты | [business-hypothesis-check](../../skills/business-hypothesis-check/SKILL.md) |
| Свежие внешние сигналы, когда нужны | [last30days](../../skills/last30days/SKILL.md), через его локальный launcher |
| Обслуживание NMT | [nmt-update](../../skills/nmt-update/SKILL.md), только по запросу и через канонический репозиторий |

Здесь нет второй копии скиллов: папка продукта хранит состав, версии и сценарии,
исходники живут в `skills/<name>`. Самостоятельные NMT-скиллы сохраняют локальный
канон и исходный контракт путей.

Анкеты, исследование, разработка, выпуск и осмотр продукта — доступные по задаче
возможности уже существующего установщика: `to-questionnaire`, `research`,
`task-delivery`, `deployment`, `product-care`. Они не дублируются и не являются
обязательными зависимостями каждого разбора. При необходимости на новом хосте
их устанавливают обычным `--skills-only` режимом этого репозитория.
Для Bitrix24 и amoCRM доступен отдельный [CRM-пак](../crm-business-pack/README.md)
с входом `crm-implementation`. Он принимает согласованный процесс; его наличие
и установка проверяются отдельно, копия в этот пак не входит.

CWS подключается из проекта, если она есть; её код и клиентский контекст не
публикуются и не копируются внутрь этого продукта.

## Установка и проверка

Из корня репозитория, для уже настроенных CLI и Desktop:

```bash
python3 scripts/install.py plan --skills-only --pack business-automation --all
python3 scripts/install.py install --skills-only --pack business-automation --all
python3 scripts/install.py verify --skills-only --pack business-automation --all
```

Установщик сохраняет найденный общий modern-каталог и его алиасы. Для своего
известного каталога добавьте `--business-root /absolute/native/skills`;
для отдельной среды выберите `--wsl` или `--desktop`. Для нескольких новых
сред с разными каталогами установщик требует явный выбор вместо угадывания
native discovery. Он не создаёт дополнительные алиасы автоматически.

Проверяются уникальность имён среди известных roots, точные хеши, блокировка
записи, источник и исходное состояние перед заменой. Резервные копии находятся
вне discoverable skills на файловой системе целевого каталога. Настройки
моделей, профили, роли, политики, аккаунты и посторонние навыки не входят в этот
режим. Повторная установка той же версии должна быть no-op.

Новый сеанс должен загрузить актуальный каталог. Пример запроса:

> `$business-work` Клиент хочет настроить CRM с нуля. Разбери контекст,
> выбери первый участок, опиши будущую работу и способ проверить внедрение.
> Сейчас только анализ и проектирование.

## Версии, источники и проверка пользы

В 1.1.0 добавлена собственная подготовительная процедура customer-research-prep.
Она связывает решение бизнеса, уже известный контекст, отбор участников,
человеческие вопросы с уточнениями или самостоятельную анкету и будущий разбор.
Группы отбора сохраняются отдельно от доказанных AJTBD-сегментов. Следующий
анализ настоящих ответов использует существующие NMT/marketing возможности.
Это дополнение к публичному закреплённому канону, а не копия закрытого курса
или официальный новый продукт NMT. [Методы и происхождение](../../skills/customer-research-prep/references/sources-and-handoff.md).

Пример запроса:

> `$customer-research-prep` Изучи материалы предыдущей встречи и подготовь
> короткие вопросы с уточнениями для следующей. Покажи, что ответы помогут
> решить. Сейчас только подготовка.

[Правила обслуживания](../../skills/business-work/references/maintenance.md):
сначала кандидат канонического репозитория, версия/пины и проверка, затем
разрешённая публикация и установка точной версии. Автообновление upstream и
проектные installers сторонних авторов не используются.

Сохранены адаптации набора 1.2: пути/контракты NMT, приоритет правил хоста,
русский язык и существующий владелец состояния, отключённые telemetry/update;
last30days запускается без извлечения browser cookies и новой настройки
провайдеров. Внешние business-analysis/process-mapping/change-management
скиллы остаются исследованными кандидатами, не скрытыми зависимостями.
[Источники и границы](../../skills/business-work/references/sources-and-reuse.md).

Структура и учебные [сценарии](validation/SCENARIOS.md) проверяют инструкцию и
переносимость, но не живую CRM, принятие сотрудниками или бизнес-эффект.
Пилот проводится на одном разрешённом участке; найденный повторяемый пробел
определяет необходимость следующего компонента.

Лицензии сторонних компонентов сохранены отдельно: [THIRD_PARTY](THIRD_PARTY.md).
Публичность репозитория не меняет их условия и не является общей лицензией
на остальные материалы репозитория.
