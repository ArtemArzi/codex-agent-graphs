# Бизнес-модель

Версия: **0.1.0**. [Состав](pack.json). Общий вход:
[business-work](../../skills/business-work/SKILL.md).

Пак помогает найти возможность, связать покупателя и исполнение с деньгами,
проверить существенные предположения и выбрать следующий ограниченный шаг.
Входы: «ищу новое дело» и «вижу повторяющийся процесс у клиентов».
Результатом может быть услуга, продукт, ещё один тест или остановка.

| Возможность | Единственный исходник | Результат |
| --- | --- | --- |
| Общий маршрут | [business-work](../../skills/business-work/references/business-model.md) | Вопрос, нужный навык, решение и переход к существующим владельцам |
| Спроектировать модель | [business-model-design](../../skills/business-model-design/SKILL.md) | Покупатель, ценность, исполнение, канал, деньги, зависимости и следующий тест |
| Проверить экономику | [business-economics](../../skills/business-economics/SKILL.md) | Затраты, труд, мощность, денежные сроки, чувствительность |
| Из процесса в продукт | [process-to-product](../../skills/process-to-product/SKILL.md) | Повторяемое ядро, настройки, исключения, форма и проверка следующей поставки |

Для этого маршрута исходный рынок Россия, если пользователь не выбрал другой.
Зарубежные модели служат референсами; спрос, цена, канал и исполнение проверяются
в целевом рынке. [Правило переноса](../../skills/business-work/references/market-context.md).

Исследование, интервью, оффер, pricing, NMT, проверка гипотез, код и выпуск
сохраняют своих владельцев. Это дополнительные доступные возможности, не
обязательная цепочка или автоматически устанавливаемые зависимости. Без них
допустим ограниченный обычный разбор с обозначенными пределами. Специальный
NMT-канон по памяти не воспроизводится.

## Использование

После установки достаточно обычного запроса:

> Используй $business-work. У нескольких клиентов приходится вручную собирать
> статус заказов. Разбери, можно ли повторять такую поставку как услугу или продукт
> для России. Пока разрешены анализ и подготовка проверки.

Отдельные навыки можно вызвать напрямую. Существующее дело хранит состояние,
источники, расчёты и решение; отдельный tracker/controller не создаётся.
Небольшой прототип может проверять техническое неизвестное до большой разработки.
После выпуска факты применения и поддержки возвращаются в бизнес-модель.

## Установка и обновление

Из проверенной версии репозитория:

    python3 scripts/install.py plan --skills-only --pack business-model --all
    python3 scripts/install.py install --skills-only --pack business-model --all
    python3 scripts/install.py verify --skills-only --pack business-model --all

Выбор среды/корня, aliases, backups и native discovery описаны в
[общем руководстве](../../docs/INSTALLATION.md). Пак устанавливает четыре
перечисленных исходника, включая общий business-work. Модели/профили/политики
не входят в эту область установки.

Несколько паков используют один business-work. Устанавливай их из одной версии
репозитория. Старый checkout Business Automation может заменить общие инструкции
старой версией. Не устанавливай второй физический экземпляр с тем же именем.
Business Model отказывает при drift до записи. Сравни локальные изменения с
исходником и сохрани их. Если уже установленный Business Automation совпадает
с известной предыдущей версией, после проверки обнови его из этого checkout его
штатным installer, затем установи Business Model. Это обновление допустимо только
при согласованной исходной версии; неизвестные правки не заменяй ради продолжения.
