# Состав, зависимости и перенос на другой компьютер

## Что получает получатель репозитория

`marketing-cycle` 0.1.0 устанавливает пять навыков из [pack.json](pack.json). Все их собственные инструкции, references, native metadata, установщик и проверки находятся в этом репозитории. Для установщика нужны Git и Python 3.11+; runtime dependencies пакета пусты. Доступ к рекламным кабинетам, CRM, данным и разрешение на внешние действия определяются конкретной задачей.

`reused_capabilities.required=false` означает условное использование доступного специалиста. Это не список автоматически устанавливаемых зависимостей. Без них пять навыков выполняют ограниченный разбор по собственным инструкциям и обозначают недоступную специализацию. Полная библиотека уже настроенного компьютера не переносится одной командой установки этого пака.

## Дополнения, уже включённые в тот же GitHub-репозиторий

Все 17 имён ниже имеют собственный `skills/<имя>/SKILL.md` в этом checkout. После клонирования их можно явно читать из исходников; это не равнозначно нативной установке. Не копируй вручную только SKILL.md: профильный навык может использовать свои references, скрипты и правила установки.

| Владелец поставки | Дополнения, используемые маркетинговым пакетом | Путь установки или использования |
| --- | --- | --- |
| [Business Automation](../business-automation/README.md) | business-work, business-hypothesis-check, nmt-market-research, nmt-analyze-interviews, nmt-craft-value-proposition, nmt-craft-go-to-market | Штатный `--skills-only --pack business-automation`; состав шире этих шести |
| [Business Model](../business-model/README.md) | business-economics, business-model-design | Штатный `--skills-only --pack business-model`; также включает общий business-work и process-to-product |
| [Общая инженерная поставка](../../docs/INSTALLATION.md) | market-research, research, task-delivery, deployment, seo, web-measurement, website-standards, reliable-leads | Проверить текущий `SKILLS` в scripts/install.py и план общего `--skills-only`; он устанавливает и другие инженерные навыки |
| [CRM Business Pack](../crm-business-pack/README.md) | crm-implementation | Исходники и инструкция этого продукта; общий `--pack crm-business-pack` не поддерживается |

Выбирай только нужные дополнения. Для двух бизнес-паков используй один проверенный checkout, поскольку business-work общий. Для каждого выбранного scope сначала `plan`, затем `install` и `verify` с теми же аргументами; `--all` выбирает среды WSL/Desktop. [Полная инструкция](../../docs/INSTALLATION.md) описывает общий каталог, конфликт имён, drift и обнаружение навыков. NMT сохраняет собственное происхождение и лицензию CC BY-NC-SA 4.0, указанную в его [манифесте](../business-automation/pack.json); лицензия маркетингового пака не меняет условия дополнений.

Таким образом, GitHub содержит весь самостоятельный Marketing Cycle и 17 повторно используемых дополнений. Ещё четыре имени имеют явные отдельные маршруты. Это поставка с описанными условными дополнениями, а не единый установщик всего текущего рабочего окружения. Контекст компании остаётся у компании, кабинеты и секреты не являются частью пака.

## Проверка получателем

1. Клонировать этот репозиторий и выбрать конкретный проверенный commit.
2. Выполнить команды Marketing Cycle из [README](README.md#установка-и-обновление). Убедиться, что установщик выбрал ожидаемые home/root и только пять навыков.
3. Проверить доступность нужных дополнений по таблицам выше. Если специалист отсутствует, читать доступный источник либо продолжать ограниченным методом с явно указанным пробелом.
4. Открыть новый сеанс и проверить native discovery. Проверка файлов сама по себе не подтверждает выбор навыка моделью или доступность интеграций.
5. Начать с [START-HERE](START-HERE.md) на условной компании. Клиентский пилот, фактическая публикация, применение командой и коммерческий эффект проверяются отдельно.
