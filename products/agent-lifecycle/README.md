# Agent Lifecycle Pack

Версия **0.1.2**. Вход: [`$agent-project-design`](../../skills/agent-project-design/SKILL.md).
Пак для создания, проверки и передачи AI-агентов: RAG, продажи/CRM,
администраторы, поддержка, исследование, разработка и фоновые задачи.

Основной путь: задача и ценность → контракт → обвязка и интеграции → состояние
и знания → eval/E2E → выпуск → пилот, приёмка и передача → использование и эффект.
Начинайте с нужного этапа; существующие решения повторно не согласуются.

| Навык | Назначение |
| --- | --- |
| [agent-project-design](../../skills/agent-project-design/SKILL.md) | Общий вход, агентский контракт, архитектура и выбор возможностей |
| [agent-memory-lifecycle](../../skills/agent-memory-lifecycle/SKILL.md) | Происхождение, актуальность, исправление, удаление, изоляция и проверка памяти |
| [agent-outcome-e2e](../../skills/agent-outcome-e2e/SKILL.md) | Реальный путь пользователя, модель, инструменты, состояние, эффект, сбои и восстановление |
| [agent-commercial-delivery](../../skills/agent-commercial-delivery/SKILL.md) | Предложение, пилот, экономика, клиентская приёмка, передача и сопровождение |

Четыре папки `skills/<name>` — единственные исходники новых навыков. Папка
продукта хранит состав, источники, примеры и проверки, без второй копии навыков.
Существующие software/business/eval возможности перечислены в [pack.json](pack.json)
как доступные по задаче: они не копируются, не устанавливаются автоматически
и не становятся обязательными зависимостями каждого вызова. При отсутствии
компаньона используйте штатный процесс и встроенные руководства, сохраняя границы
непроверенного. Пак не добавляет runtime, controller, сервер, обязательные роли,
SDK, облако, vector DB или долгосрочную память каждому агенту.

**E2E в центре пака:** входное событие → рабочий канал → настоящая модель и
обвязка → инструменты → сохранённое состояние → фактический результат → ответ
пользователю. Проверяются также необходимые права и подтверждения по пути.
Scripted/replay, live model, локальный adapter, provider sandbox/live,
пользовательская приёмка и бизнес-эффект отмечаются отдельно.

## Использование

Дайте Codex путь к `skills/agent-project-design/SKILL.md` из этой папки и задачу:

> Используй agent-project-design из этого пака. Нужен агент-продавец для CRM.
> Сначала изучи существующий процесс, предложи ограниченный первый сценарий
> и опиши E2E-проверку правильной сделки, дублей и восстановления после таймаута.
> Сейчас только проектирование.

После установки используйте `$agent-project-design`; отдельные задачи можно
начинать с `$agent-outcome-e2e`, `$agent-memory-lifecycle` или
`$agent-commercial-delivery`. Наличие файлов в репозитории само по себе не
подтверждает discovery в текущем сеансе.

## Проверка и установка из репозитория

Пак опубликован как отдельный продукт в `ArtemArzi/codex-agent-graphs`.
Навыки хранятся один раз в `skills/agent-*`; общий установщик и проверки
поддерживают его состав через `pack.json`. Существующие software- и бизнес-скиллы
сохраняют своих владельцев. Не копируйте второй экземпляр навыка в другой
каталог обнаружения.

Проверка добавленного дерева:

```bash
python3 scripts/check_agent_pack.py
python3 -m unittest discover -s tests -p test_agent_pack.py -v
python3 scripts/check_all.py
```

Последняя команда принадлежит общему репозиторию и нужна перед его коммитом.
Отдельный архив содержит инструкции и проверку упаковки; установщик берётся
из полного репозитория. Проверка умеет
проверять имена в явно выбранных каталогах:

```bash
python3 scripts/check_agent_pack.py --skill-root /absolute/first/skills --skill-root /absolute/second/skills
```

Одинаковые физические каталоги через алиасы считаются одним местом. Два разных
места с одним из четырёх управляемых имён — конфликт. Если установленная копия
отличается от исходника, это отмечается; проверяющий скрипт ничего не заменяет.

Пак зарегистрирован в штатном manifest-aware установщике. Из проверенной
ревизии репозитория:

```bash
python3 scripts/install.py plan --skills-only --pack agent-lifecycle --all
python3 scripts/install.py install --skills-only --pack agent-lifecycle --all
python3 scripts/install.py verify --skills-only --pack agent-lifecycle --all
```

Используется существующий общий modern-каталог CLI/Desktop; intentional aliases
сохраняются. Для явно выбранного общего каталога добавьте `--skill-root PATH`;
`--business-root` остаётся совместимым алиасом. Каталог должен быть виден выбранным
средам; неоднозначный новый хост требует явного выбора. Устанавливаются только
четыре managed-навыка, без второй копии в legacy roots, изменения config/models,
ролей или подключений. Проверяются реальные объявленные имена, включая вложенные
папки, точные хеши и исходное состояние под общей блокировкой. Повтор той же
версии — no-op. Обнаруженный agent skill drift останавливает установку до явной
сверки версии и локальных правок; существующий business-pack режим сохраняет своё
прежнее поведение. Обновление источников само по себе не обновляет установку.

### Native-каталог каждой среды

Общий физический каталог должен быть доступен через пользовательский
`$HOME/.agents/skills` каждой среды. WSL HOME и Windows USERPROFILE различаются.
Один `CODEX_HOME/.agents/skills` не гарантирует загрузку Windows Desktop;
`install.py verify` подтверждает файлы и manifest, а native `skills/list`
подтверждает фактическое обнаружение. Это разные проверки.

При общем каталоге сохраняйте существующие алиасы. Если Windows native-путь
отсутствует, можно создать NTFS junction на выбранный общий каталог. Сначала
проверьте все объявленные имена в общем и legacy-каталогах, отключённые пути
`skills.config` и отсутствие занятого назначения. Junction открывает Desktop
весь общий каталог, включая ранее установленные software/CRM/business навыки.
При конфликте не заменяйте существующие папки. Не делайте вторую копию навыков.
Откат новой ссылки удаляет только junction после проверки типа и назначения,
никогда рекурсивно его содержимое; новый пустой родитель можно убрать отдельно.

Этот хостовый шаг не выполняется установщиком автоматически. Для другого
компьютера нужны его реальные пути и проверка native-каталога. Стандартные
пользовательские пути и поддержка ссылок описаны в
[документации OpenAI](https://learn.chatgpt.com/docs/build-skills).

Для проверки discovery используйте новый сеанс. Installed-byte readback,
загрузка навыка и работа настоящего агента — разные уровни свидетельства.

## Источники и проверенные границы

[Исследовательская основа](SOURCES.md) включает материал выступления, внутренние
навыки, инженерные первоисточники, семь научных работ по ключевым разделам и
дополнительный abstract по RAG. Полные тексты видео/статей, сторонние навыки,
клиентские данные, локальные пути и секреты в поставку не включены.

[VALIDATION.md](VALIDATION.md) различает проверку упаковки, учебное применение
инструкций и не выполненный live E2E. [Учебные запросы](validation/SCENARIOS.md)
помогают проверять следующие версии. Пак не обещает продажу или отсутствие
редких отказов: фактическая сделка, применение людьми и эффект наблюдаются отдельно.

Обновление: изменить единственный исходник в `skills/<name>`, поднять затронутую
версию и версию продукта, проверить инструкции и файлы, пересоздать manifest
явной командой `python3 scripts/check_agent_pack.py --write-manifest`, затем
проверить и упаковать точный кандидат. Обновление исходника не меняет глобальную
установку. [Происхождение и условия внешних материалов](THIRD_PARTY.md).
