Независимое применение инструкций к шести [синтетическим запросам](validation/SCENARIOS.md):

| Ситуация | Полученное решение |
| --- | --- |
| A. Новый агент | Один агент, узкие инструменты и владельцы состояния; лишняя инфраструктура не добавлена; существенные неизвестные сохранены |
| B. Потеря ответа и дубль | FAIL локального scripted/adapter пути; реальная модель и production не объявлены проверенными; предложена сверка исходной операции |
| C. Исправление/удаление памяти | FAIL активного удаления и изоляции; удаление backups остаётся INCONCLUSIVE |
| D. Правильный refund без согласия | Общий FAIL по policy trajectory, несмотря на верное состояние и высокую оценку тона |
| E. Предложение клиенту | Подготовлен ограниченный пилот; 40% экономии, прибыльность, продажа и применение не признаны доказанными |
| F. Setup/fault/readback | Запрещённая попытка даёт FAIL; setup — INVALID; missing readback — INCONCLUSIVE; несработавшие faults не засчитаны проверкой восстановления |

Это независимое учебное применение по предоставленным наблюдениям, без сравнения
с baseline, слепого holdout и запуска агентского runtime. Оно показывает полезные
решения по инструкции в этих случаях, а не общую надёжность будущих агентов.

Проверки источников опираются на предшествующее исследование и выборочную
независимую сверку точных arXiv-идентификаторов; эксперименты авторов не повторялись.

Интеграция 0.1.1 проходит 13 изолированных тестов установки: общий каталог и
алиасы, отсутствие дублей в legacy roots, сохранность защищённых настроек,
повторный no-op, отказ при drift, полная проверка manifest, блокировка, изменение
источника и откат собственных записей с сохранением чужих правок. Штатные
business/legacy тесты и `scripts/check_all.py` запускаются перед публикацией
на точном кандидате поверх GitHub baseline 907bb8da1e97538949b30223fd38f09d6bfe4f7f.
Исторический PASS таблицы выше относится к первоначальной поставке 0.1.0.

Глобальная установка проверяется отдельно после публикации через план,
installed-byte readback, повторный no-op и новый native `skills/list`.
Наличие этой процедуры в исходниках не является свидетельством её выполнения
на конкретном хосте; результат операции хранится в локальном отчёте установки.
Live agent/model/provider E2E, развёртывание, клиентская приёмка, продажа и
бизнес-эффект этими проверками не подтверждаются.
Архив считается поставкой только после успешной команды упаковки и readback.
Неуспешная операция может оставить файл ZIP; сам факт его наличия не означает PASS.
