## Large-codebase discovery before plans and specifications

Apply this policy when a task needs a plan, specification, architecture decision or substantial explanation and the relevant execution path is unclear across multiple subsystems, depends on both repository and current external evidence, or would otherwise make the root agent spend a large share of its context on broad discovery. Keep small, local and already well-mapped tasks root-only.

- Start with a bounded orientation: `git status --short`, the root and nearest `AGENTS.md`, the documentation map, repository shape, and targeted symbol/search results. Stop broad root scanning as soon as two independent research questions are visible.
- Delegate independent read-only questions, not folders or duplicate searches. Use one `explorer` for one unclear execution path and at most two for distinct internal scopes. Never spawn more than two internal explorers; group three or more internal areas into two coherent questions and keep cross-cutting reconciliation in the root. A third child is permitted only as one `researcher` or one `$research` branch when current external evidence is material; do not use both for the same question.
- Inside `$task-delivery`, reuse its `task_explorer` roles and combined agent limits instead of creating a second delegation layer. Outside it, use the generic `explorer` and `researcher` roles already provided by Codex. Do not create a custom large-codebase agent or another graph for this policy.
- Give every child an exact question, path or source scope, known facts, exclusions and required evidence packet. Internal packets must contain relevant paths and symbols, the observed execution path, inherited constraints, tests, risks and unknowns. External packets must distinguish sourced facts from inference and link primary sources.
- Let the root inspect only unassigned or cross-cutting seams while children run. The root remains the sole synthesis and plan owner; children do not write the final plan or specification.
- Treat completion of every required child as a join barrier. Do not finalize a plan or specification while one is still running. Use one discovery wave; issue a same-scope follow-up only for a material evidence gap. A timeout is not completion: wait again, narrow the same branch, or explicitly cover the missing scope in the root and report reduced confidence.
- After the join, reconcile contradictions, perform one targeted gap-closing pass, and persist a compact research basis in the project's existing plan or scratch owner before an expected compact and before final planning. Include repository state, branch findings with file evidence, external sources used, invariants, tests, unresolved gaps and plan implications.
- After compact, reopen the persisted research basis and the decisive source files. Never treat the compact summary alone as evidence for the plan.
